# Agent UI gateway v1

The new ordinary-UID APK `org.agentos.agent` uses this narrow interface to the existing system assistant. It must have the same signing certificate and declare `org.agentos.permission.AGENT_CLIENT`. The provider verifies both the signature permission and the caller's sole package name. The existing root broker socket continues to accept only root/system UID.

Call `ContentResolver.call(Uri.parse("content://org.agentos.assistant.agent-gateway"), action, jsonParameters, null)` on a worker thread. Read `Bundle.getString("result")` as JSON. Normal response is `{ok:true,result:{...}}`; failure is `{ok:false,code:"...",message:"..."}`. Codes contain no broker error details or credentials.

Responses over 256 KiB return `{ok:true,resultUri:"content://org.agentos.assistant.agent-gateway/result/<uuid>"}` instead. Immediately read this URI with `ContentResolver.openInputStream` and parse the **complete original envelope**. The single-use buffer expires in 30 seconds; at most 8 buffers / 16 MiB remain in memory. No transcript truncation, file export, URI grants, or second conversation store is used. A response over 8 MiB fails explicitly. Do not retry a mutating action automatically if its IPC outcome is unknown.

| Action | Parameters | Result |
|---|---|---|
| `listThreads` | `{}` | Existing broker `{data:[thread summary],source:"app-server"}` |
| `createThread` | `{}` | Existing `{thread:...}`; prepares the real harness, does not start a model turn |
| `resumeThread` | `{threadId}` | Validates and selects this exact native conversation, then returns its snapshot; does not start a turn or alter drafts/pending content |
| `readSession` | `{threadId,refresh?:boolean,statusOnly?:boolean}` | `{thread,native,historyComplete,historyStatus,knownEmpty,totalTurns,task?,request?,runtime?}` |
| `mainReply` | `{action:"read",threadId,turnId,replyId?}` | Logical native read envelope: bounded summaries or exact canonical primary reply; no inference |
| `subscribeSession` | `{threadId,brokerEpoch?:string,afterSeq?:number}` | `{subscriptionId,streamUri}`; read-only UID-bound JSONL pipe |
| `unsubscribeSession` | `{subscriptionId}` | `{closed:true}`; closes only this view subscription |
| `composer/read` | `{threadId}` | `{threadId,revision,text,attachments,recovery,pendingReceipts}` |
| `composer/write` | `{threadId,revision,text}` | Draft snapshot after a revision-checked text replacement |
| `composer/import` | `{threadId,text}` | Current draft snapshot after importing legacy text, with retries deduplicated by conversation and exact text |
| `composer/move` | `{threadId:"",revision,targetThreadId}` | Target draft snapshot after moving the new-conversation draft |
| `composer/attach` | `{threadId,expectedRevision,name,mime,uri?}` plus optional `extras.attachment` read-only FD | Draft snapshot with one imported attachment. Send either the FD or a granted `content:` URI. |
| `composer/removeAttachment` | `{threadId,expectedRevision,attachmentId}` | Draft snapshot after removing that attachment |
| `composer/submit` | `{threadId,revision,requestId,action,attachmentIds}` plus `expectedTurnId` for `steer` or `panelId,expectedSourceVersion` for `continue` | Receipt for a frozen draft and target. The `sendMessage` action starts a new turn. |
| `composer/receipt` | `{threadId,requestId}` | Read-only receipt lookup |
| `composer/settle` | `{threadId,requestId}` | Receipt and revision-checked retirement when delivery is confirmed |
| `composer/release` | `{threadId,requestId}` | Draft snapshot after releasing a pending request and preserving recoverable content |
| `composer/handoff` | `{threadId,handoffId,text}` | Draft snapshot after applying a handoff once and saving any displaced draft |
| `composer/preserveDraft` | `{threadId,recoveryId,text}` | Draft snapshot after preserving an edit in recovery without changing the active text |
| `composer/restore` | `{threadId,expectedRevision,recoveryId}` | Draft snapshot after restoring a saved draft into an empty editor |
| `composer/restoreTask` | `{threadId,expectedRevision,taskId}` | Draft snapshot after restoring a failed task from that conversation |
| `composer/options/read`, `composer/options/write` | `{threadId}` or `{threadId,options}` | `{threadId,options,effective,models}`. `null` removes a thread override. |
| `sendMessage` | `{threadId,text,requestId}` | `{threadId,requestId,taskId?,state,code?,replayed,createdAt}` |
| `steer` | `{threadId,text,expectedTurnId,requestId}` | Durable `{requestId,threadId,state,code?,result?,replayed,createdAt}`; exact current turn required |
| `interrupt` | `{threadId,turnId}` | Native `turn/interrupt` result; pauses an active goal before interruption |
| `cancelQueued` | `{threadId,taskId}` | `{threadId,taskId,cancellationRequested:true}`; same-thread queued task only; a started turn requires `interrupt` |
| `answer` | `{threadId,key,response}` | Native response receipt; supported pending request must belong to the same thread |
| `getWorkspaces` | `{threadId}` | `{schema:"taku.agent-workspaces/1",screens:[lease with previewUri]}` |
| `openWorkspace` | `{threadId,screenKey,generation}` | `{opened:true}`; opens existing native control UI after exact lease check |
| `requests/list`, `requests/read`, `requests/submit`, `requests/respond`, `requests/cancel` | `{threadId,key?,values?,response?}` | Request identities, a request as a form, an answer by form field (secrets in `extras["credential"]`), a raw response, or cancellation |
| `openSettings` | `{page?:"models"\|"system"\|"workspaces"}` | `{opened:true}` for the matching Expo page |
| `readTaskDetail` | `{taskId}` | `{taskId,state,prompt,message}` from the native task store |
| `manageSystemAi`, `manageAssistant` | `{operation,...fields}` | Shared settings or native management result. See `taku-system-ai-settings` and `taku-open-access`. |
| `pluginManager` | `{operation,argument?:string,name?:string,arguments?:object}` | God Mode manager envelope inside the gateway result; see operation and error contract below |
| `decide` | `{state,questions}` | Jev `{answers}` for 1–64 `choice` questions (one per composition candidate); uses the Agent settings Jev switch and model (`JEV_DISABLED`, `JEV_NOT_CONFIGURED`) |
| `generateUi` | `{requestId,instructions,prompt,catalogVersion}` | `{text,model,elapsedMs,usage}` from the system text model (consumer `agent-ui`); non-streaming, output is untrusted JSONL the app validates |
| `panels` | `{operation,args}` | Forwards one `PanelRegistry` catalog operation and returns its envelope unchanged; `operation` is the short suffix `describe`, `list`, `get`, `pin`, `unpin`, `rename`, `move`, `open`, `navigation` or `continue`; see the panel contract below |
| `cardView` | `{operation,args}` | Forwards one card-state operation, `operation` is `read` or `apply`, and returns the canonical card state; see the panel contract below |

IDs use lowercase UUID format; card keys are `[a-z0-9-]{1,64}`. Text is 1–16000 nonblank characters. Requests are at most 48000 characters, except `generateUi` (96000). Unknown actions and parameters are rejected. No arbitrary broker RPC, model credentials, commands, or caller-defined intents are accepted. Plugin package arguments follow the plugin manager's operation contract. The client handles foreground locale and theme; the broker remains authoritative for session and task state.

`panels` is the app-only view of the same interface the open-access provider exposes as `panels/*`. `args` carries exactly that operation's parameters (`panelId`, `source`, `requestId`, `title`, `expectedListRevision`, `expectedMetadataRevision`, `expectedSourceVersion`, `beforePanelId`, `limit`, `cursor`, `text`) and is validated once, in the native registry. It never returns card content, model output or task success: a panel's body is read from the native matter projection, and business actions keep going through the existing matter dispatch. `{operation:'describe'}` returns the accepted methods, field limits, contract version and error codes so a client does not hardcode them; its contract version is `taku.panels/1`, and a client that does not accept it shows the update-required error instead of guessing. `panels/get` also returns the current `listRevision` so a caller can Unpin without a second list read, together with `sourceState` (`{state:"current"|"offline"|"thread-unavailable"|"unavailable",observedAt?,code?}`) and `capabilities` (`canOpen`, `canContinue`, `canUnpin`). Failures come back as `{ok:false,code,message}` with `INVALID_ARGUMENT`, `UNKNOWN_METHOD`, `PANEL_NOT_FOUND`, `REPLY_INCOMPLETE`, `SOURCE_CHANGED`, `SOURCE_UNAVAILABLE`, `SOURCE_THREAD_NOT_FOUND`, `SOURCE_ALREADY_PINNED`, `PANEL_UPDATE_AMBIGUOUS`, `STALE_SOURCE`, `VERSION_CONFLICT`, `LIST_CHANGED`, `IDEMPOTENCY_CONFLICT`, `MATTER_STORAGE_FULL` or `STORAGE_ERROR`. `panels/open` only reports that navigation was accepted.

`cardView` reads and writes the same card state the GUI submits, while `readMatter` and `dispatchMatter` keep their existing shapes and ownership. A matter snapshot additionally exposes derived `pin` (`canPin`, `panelId`, `source`, `listRevision`, optional `code`), the canonical `cardView` state and a `presentation` that is either the trusted primary reply or the ordinary matter request. A pending, superseded or failed source cannot gain `canPin` from client data or from `request.mode`.

The retired app-only actions `savePanel`, `readPanel` and `listPanels` no longer exist, and neither does the `mode:'panel'` Keep list they served. A card with `mode:'panel'` keeps only its layout meaning. Pinning is the native `panels/pin` operation on a completed, catalog-validated reply; drafts and selections stay in card state instead of a kept panel record.

`pluginManager` accepts `ping`, `list`, `show`, `install`, `remove`, `enable`, `disable`, `reload`, `tools`, `tool`, `checks`, `run-check`, `call-tool`, `evidence`, or `local`. `operation` is a nonblank string of at most 64 characters. Optional `argument` and `name` are nonblank strings of at most 4096 and 256 characters. Optional `arguments` is a JSON object. Invalid inputs return the gateway codes `UNSUPPORTED_PLUGIN_OPERATION`, `INVALID_operation`, `INVALID_argument`, `INVALID_name`, `INVALID_arguments`, or `UNSUPPORTED_PARAMETER`. The system assistant forwards accepted requests to the existing `taku-godmode` socket. Manager failures remain inside the normal gateway result, such as `{ok:true,result:{ok:false,error:{code:"UNAVAILABLE",message:"..."}}}`. Callers must inspect that inner envelope. This action does not add another plugin store or executor.

Normal conversation turns use the main model's `@taku.reply/1` component/data stream. Native code parses and validates each complete record, publishes accepted prefixes as `turn.mainReplies[id]`, and derives one human-readable answer from the same typed data. Each reply has schema `taku.main-reply/1`, stable native `id`/`key`, monotonic `revision`, `readableText`, `provenance:{kind:'primary-assistant-reply',threadId,turnId,anchorOrdinal,anchorHash,sourceItemIds,contractHash}`, `lifecycle`, and `card:null|{request,view,assembly}`. Lifecycle phases are `streaming`, logically `sealed`, `completed`, `failed`, and `interrupted`. Sealing does not prove native completion. Primary replies never invoke a second formatter, Jev, `generateUi`, or layout inference retry.

Presentation requests retain strict V2 typed blocks, items, reply actions and stable semantic IDs. Primary views are supplied by the main model, catalog-validated by native code, and rendered directly; `metrics.level:'primary'` carries no separate inference usage. Component content binds semantic data, while existing node identity/type/parent/props stay fixed and new complete nodes append. A primary record cannot supply `actionRef`, source authority, confirmation receipts or business success. Only a completed native reply can admit Matter capabilities. A card with `mode:'panel'` offers Pin to Panels only after native completion, through `panels/pin`; incomplete replies have no pinning path and keep only local `/ui` draft and selection state. Native storage resolves the canonical reply/view and rejects a client-authored `record.reply`. Existing actual tool/Panel cards retain their independent layout behavior and native execution/confirmation owner.

Chat layouts use catalog `taku-chat-feed-1` and the shared Feed drawing implementation. New presentation configuration excludes raw colors, gradients and arbitrary visual overrides. Reading an older V2 request produces a current, non-mutating display projection that omits its historical decoration. Original native records, typed source values, stable IDs and command capabilities are retained. Saved or cached views must pass current catalog and binding admission; rebuilding an obsolete view preserves `/ui` drafts, selections and expansion.

An optional native agent-message `phase` may be absent or JSON null. Explicit commentary and analysis remain excluded from primary reply input. Ordinary unframed prose stays text; malformed framed output retains its accepted prefix with a failure and never appears as raw wire JSON. The per-turn contract reaches existing frozen threads. Non-chat `outputSchema` tasks, MemoryGen and realtime keep their own formats.

Standard on-device Agent access reads the same canonical native reply without the app-only gateway permission:

```sh
content call --uri content://org.agentos.assistant.open-access --method reply/read \
  --arg '{"threadId":"THREAD_UUID","turnId":"TURN_ID"}'
content call --uri content://org.agentos.assistant.open-access --method reply/read \
  --arg '{"threadId":"THREAD_UUID","turnId":"TURN_ID","replyId":"REPLY_ID"}'
```

`threadId` and `turnId` are required strings identifying the actual native turn; `replyId` is optional. Without it, the result contains at most the last 32 reply summaries, each with at most 4000 characters of readable text. With it, the result contains the full canonical reply. Check the logical `ok` envelope inside `Bundle.result`. Missing/unknown fields, wrong types or oversized arguments return `{ok:false,error:{code:'INVALID_ARGUMENT',message:'INVALID_ARGUMENT'}}`; unavailable objects return `THREAD_UNAVAILABLE`, `TURN_UNAVAILABLE`, or `REPLY_UNAVAILABLE`. The protected app gateway offers `mainReply` with the same read parameters. The root/system native socket uses `{op:'mainReply',action:'read',threadId,turnId,replyId?}`. These reads perform no model inference.

Body updates use the ordered subscription described in [session streaming](SESSION_STREAMING.md). The relay adds its own epoch/sequence cursor; these are not fields or replay guarantees of the upstream Codex protocol. A healthy client polls `readSession(statusOnly:true)` for task and approval state without rereading the body. Full reads remain available for initial hydration and fallback.

Call `resumeThread` on an explicit conversation selection so native system entry and the React UI agree on the selected conversation. Serialize selection requests and discard stale UI reads; concurrent selection requests can otherwise persist preferences in response order. Regular `readSession` polling is read-only and never changes the selected conversation. A selection failure leaves drafts, Home pending content and task state intact.

The broker's `thread/read` control returns `{threadId,loaded:true}` after loading the native conversation. `resumeThread` validates this acknowledgment before reading the projection. `threadUnavailable:true`, a missing load acknowledgment, or a different thread ID returns `THREAD_UNAVAILABLE`.

`readSession` returns native conversation items. Normal polling reads the current projection. `refresh:true` requests complete native history while no turn is active. Completeness survives only while the known turn and item identities remain visible. Missing evidence sets `historyStatus:"unknown"` and `knownEmpty:false`. `native.requests` contains the exact thread's phone questions, phone approvals, and nonsecret user-input requests. `native.unsupportedRequestCount` directs the UI to the Kotlin request form. The provider never adds authorization payloads to the session projection.

`sendMessage` reuses TaskBroker publication with the supplied conversation ID and existing model preferences. It sends text only; it never inherits another editor's screenshot or attachments. Generate one `requestId` per explicit send and retain it until the result is reconciled. The durable receipt prevents automatic replay after process death or a lost IPC response. `queued` means accepted for execution, not task success; `publishing`/`deliveryUnknown` must retain the draft and request inspection, not resubmit under a fresh ID.

`state:"notSent"` with matching `threadId` and `requestId` is the sole definitive rejection receipt. It proves that the read-only preflight failed before the publication or RPC callback ran. Its `code` can be `THREAD_UNAVAILABLE`, `THREAD_BUSY`, `THREAD_QUEUED`, `TURN_CHANGED` or a sanitized read failure. The client may remove its pending record, retain the editable draft, and use a new ID for the next explicit send. Replaying the rejected ID only returns its original rejection; it never starts executing later. Do not infer non-delivery from an error code alone: identical-looking errors after publication starts remain `deliveryUnknown`, and an IPC error or malformed/mismatched receipt must retain the original pending record.

The server rejects a new publication while this session has a published TaskBroker task without a `done` marker, even before `native.activeTurnId` exists. `readSession.task` contains the existing `id`, `state`, `message`, plus `published`, `turnStarted` and `cancelRequested`. States include `queued`, `running`, `completed`, `failed`, `needs_user` and `cancelled`. Treat a published queued/running task as busy: before a turn starts, Stop calls `cancelQueued`; after `native.activeTurnId` appears, Stop calls `interrupt`. A cancellation receipt only requests cancellation; wait for the actual task state. A race returning `TURN_STARTED` requires a refreshed snapshot before deciding how to stop.

Same-thread preflight and publication are serialized through a session gate. Receipt reservation/finalization hold only the receipt lock; MatterRuntime releases its monitor before submission callbacks. Audio invalidations use an asynchronous serial dispatcher, so observer callbacks do not retain the audio owner's monitor.

`steer` also requires a stable UUID `requestId`. Its receipt is persisted before calling `turn/steer`; an accepted reply returns `state:"accepted"` and the original result. If the preflight proves the expected turn changed, or the pinned native runtime explicitly returns JSON-RPC `-32600` / `no active turn to steer`, the gateway first confirms the thread is idle and the previous queued task is finished, then publishes the same message as the next task. Its durable receipt retains the original request ID and records the queued task ID. A repeated call reconciles a published task through its `ready` marker without publishing twice. A transport error or other native error remains `deliveryUnknown`; repeating that same ID returns the receipt without issuing the mutation again. Existing unknown receipts cannot be converted to a new task without evidence that the old mutation was not delivered. Reusing an ID with different text or turn fails.

Preview URI: `content://org.agentos.assistant.agent-gateway/preview/<threadId>/<screenKey>/<generation>`. Read with `openInputStream` on a worker thread. The native directory read is scoped to the exact requested thread, so unrelated screens cannot delay its validation. A successful `getWorkspaces` read publishes an immutable, verified native catalog with a five-second monotonic lifetime. Frame reads share that catalog instead of performing two full directory reads per frame. They validate socket UID/PID, display identity, generation and JPEG dimensions, then recheck both the original catalog lifetime and the current exact lease before returning. New catalog responses do not renew an old frame's verification time. Selection, current read failure and current frame failure invalidate the applicable catalog; stale asynchronous failures cannot erase newer results. `openWorkspace` still performs a fresh native catalog validation. Only the selected session's admitted independent screens are exposed (maximum three). Frame bytes travel over a pipe, not a Binder Bundle. This is a view-only snapshot; touching the preview should call `openWorkspace`, never generate input from JS. Stop polling when the UI is hidden and clear stale frames on read failure.

`MirrorActivity` and `WorkspaceFloatService` are Kotlin runtime components. Workspace commands use `WorkspaceCommands`; control revisions, pointer translation, request receipts, and preview rendering keep their existing owners. Explicit Back, a confirmed Stop, and the floating preview's chat action return through `AgentFrontendLauncher.openThread` to the admitted lease's `threadId`. A supplied return-conversation extra cannot select another thread. If the Agent application cannot open, the component displays an unavailable message and keeps the workspace available. Minimizing, replacing a lease, closing the floating preview, and destroying either component do not open chat or resume execution.

Validation: `bash system/assistant/test-agent-gateway-host.sh` checks capability/parameter rejection, request/session scoping, secret-field omission, and duplicate publication across a store restart. Building or passing host checks does not establish installed IPC, emulator UI, Pixel, or ROM acceptance.

## Composer drafts

Composer commands require unlocked Android user 0. Other users receive `USER_UNAVAILABLE`. A locked user receives `USER_LOCKED` when the provider is reachable. Ordinary callers use `content://org.agentos.assistant.open-access` for the same commands, including `composer/createThread`. The signed gateway's `composer/import` handles private app upgrade data.

Pass `threadId:""` explicitly for the single new-conversation draft. For a real thread, use its lowercase UUID. Draft text can be empty and is stored as supplied, up to 16000 characters. A revision is an opaque string of at most 128 characters. The initial revision is `""` and a change returns a new revision. A write of identical text keeps the current revision.

Write and move compare the supplied revision with the source slot. A mismatch leaves both drafts intact and returns `{ok:false,code:"DRAFT_REVISION_CONFLICT",message:"DRAFT_REVISION_CONFLICT",revision:"CURRENT_REVISION"}`. Invalid fields return `INVALID_ARGUMENT`, and a request over 48000 characters returns `REQUEST_TOO_LARGE`. A failed disk write returns `DRAFT_SAVE_FAILED`.

Import ignores empty text. It loads legacy text into an empty editor. If the editor already contains different content, import adds the legacy text to the recovery list. If the current text matches, import leaves the editor as it is. Repeating the same import for the same conversation returns the current snapshot without adding a duplicate.

To move a new-conversation draft, use a fresh UUID from `createThread` and the current new-conversation revision. Move clears the source and transfers its text, attachments, saved drafts, and options. `THREAD_UNAVAILABLE` means the target or its history could not be verified. `DRAFT_TARGET_OCCUPIED` means the target has saved draft or conversation content. Both failures preserve the source.

The GUI and Open Access share `interrupt` with `{threadId,turnId}` and `cancelQueued` with `{threadId,taskId}`. An old turn ID returns `TURN_CHANGED`. Cancelling a queued task returns `cancellationRequested:true`; read the task state for its terminal result.

## Installed ordinary-UID IPC acceptance

Build the read-only probes with `bash system/assistant/build-agent-gateway-probes.sh`. This only creates development-signed test APKs; it does not install or operate any device. The device owner must first install matching assistant and Agent UI APKs. Run against one explicitly assigned emulator, never an implicit ADB target:

```sh
adb -s emulator-5590 install -r out/agent-gateway-probes/allowed.apk
adb -s emulator-5590 install -r out/agent-gateway-probes/denied.apk
adb -s emulator-5590 shell am instrument -w -e threadId EXISTING_REAL_THREAD_ID -e previewSamples 5 org.agentos.gatewayprobe/org.agentos.gatewayprobe.GatewayProbe
adb -s emulator-5590 shell am instrument -w -e expectDenied true org.agentos.gateway.denied/org.agentos.gatewayprobe.GatewayProbe
```

The positive instrumentation runs inside the installed `org.agentos.agent` process and verifies its ordinary UID, real thread list/snapshot identity, prohibited raw RPC/parameter rejection, and exact-session workspace catalog. If a real screen lease exists it reads a JPEG via the protected content URI. The negative APK has the same development signature and signature permission, but its different ordinary package must still be rejected. No message, new session, answer, cancellation, control handoff or model turn is submitted. Instrumentation may restart the UI process, so run it before collecting final screenshots and reopen the UI afterward.

Before the Expo build is available, `client.apk` is a minimal ordinary-UID APK with the exact `org.agentos.agent` package and self-targeting instrumentation. It uses only Android SDK Java, no React Native dependencies. On a development emulator with no production Agent app to preserve, the device owner may install it and run `adb -s emulator-5590 shell am instrument -w -e threadId EXISTING_REAL_THREAD_ID org.agentos.agent/org.agentos.gatewayprobe.GatewayProbe`. Later install the same-signed Expo APK with `-r` to preserve the UID; do not uninstall to work around a signing mismatch. This temporary probe proves the gateway boundary only, never the Expo bridge or actual UI. Once the Expo APK is installed, use the separate `allowed.apk` instrumentation above to test the final application's UID.

`previewSamples` accepts 1–10 (default 1) and records per-sample catalog/JPEG timings, verified counts and failure phase without conversation contents. Save the instrumentation JSON with the APK hashes and device build fingerprint. `passed:true` covers only the reported checks. `previewVerified:false` or `workspaceCount:0` means frame transport remains unverified. `largeResultPipeExercised:false` means the actual history did not exercise the oversized-result path. These are not UI layout, live streaming, mutation, Pixel or ROM acceptance; those need separate evidence from the actual APK.
