Experimental screenshots, recordings, accounts, and build outputs remain in the neighboring lab and are excluded from this project.

**Taku Agent** opens the Android system assistant drawer `AssistantSession`. `PanelActivity` is a transient entry point; `ChatActivity` is only an internal navigation alias. The main interface is chat, with its title from the native thread. Conversation lists and settings open within the drawer; light and dark themes share components. Settings use a dedicated Agent card page. Account connections use the same App Server's native account interfaces, with authorization challenges passed only through in-memory endpoints. Views, controllers, device IO, native-event projection, and background execution are separated. All execution uses the same long-lived App Server client inside TaskBroker. See the [module documentation](../../docs/agent-module.md) for structure, tests, and unfinished boundaries.

The v53 conversation UI uses Codex thread / turn / item records and native message phases as its source. `AgentConversation` preserves identity, order, and attachments. `NativeTurnPresentation` organizes text and execution records by turn and same-turn additions. `NativeConversationView` / `NativeTurnView` update existing views by stable IDs; `NativeActivityView` expands actual tool output. Execution details default to collapsed while prose remains continuous. Chinese streaming text does not wait for an English word-count threshold. Expansion preferences persist per conversation with bounds. Approvals and errors appear directly; native plans and diffs expand on demand. It invents no fixed steps, progress percentages, or result dashboards. See [continuous conversation and worklog acceptance](../../docs/reviews/conversation-worklog-2026-10-19/README.md) for implementation, references, and verification.

v55 adds “Model connection”: ChatGPT sign-in or the on-phone Magpie gateway. Providers and route groups are configured in the local management page. Codex 0.161.0 reads the catalog through `model_catalog_url`. Magpie is Codex's model gateway; Codex retains conversation, tool, approval, and stop management. DeepSeek inference still calls an online API. Execution and native-event rendering retain one path. Switching connections preserves conversations and drafts and is rejected during execution or queuing. See [on-device gateway adaptation](../../adapters/magpie-runtime/README.md) and [acceptance](../../docs/reviews/magpie-runtime-2026-10-19/README.md).

v59 changes memory decisions to bounded batch requests with leases and configuration-generation checks, at most five records per batch. Magpie still owns models and credentials; the independent Memory APK owns local recording/analysis switches and queues. See [batch acceptance](../../docs/reviews/taku-memory-batches-2026-10-22/README.md).

v58 supplies the independent Taku Memory APK with signature-protected model catalog, decision, and task bridges. It adds dynamic `taku_phone.memory_search` / `memory_get` tools while retaining Magpie, the conversation runtime, and TaskBroker. Memory is not stored in the assistant system-UID database or injected wholesale into Harness background. See [component and configuration](../memory/README.en.md) and [emulator acceptance](../../docs/reviews/taku-memory-2026-10-22/README.md).

v56 completes return navigation from the model management website. `ModelManagementActivity` starts the browser in its own task, receives the exit result, and restores the current conversation's Model connection page. Return navigation loads the draft and catalog through the existing drawer lifecycle without recreating a model session. It only handles navigation, neither duplicating the Magpie website nor embedding a WebView in the system-UID process.

v54 uses CommonMark + GFM for native message prose and process descriptions. `NativeMarkdown` parses only AST and styles; `NativeMarkdownView` reuses paragraph/code views; `NativeMarkdownTable` reuses cells. Images use a bounded asynchronous loader. Raw tool output stays unchanged. Code copies verbatim, links go through Android, and host workspace paths retain copyable addresses. Both themes share `DrawerTheme`. Desktop-specific previews such as Mermaid, LaTeX, PDF, and spreadsheet editors are not presented as supported Android features. Unknown fences remain readable, copyable source.

Parser versions, download URLs, and SHA-256 values are in `markdown-dependencies.json`. Requirements: Android SDK platform android-36, build-tools 36.0.0, JDK 17+, Kotlin/JVM compiler, Python 3, and zip. Configure `ANDROID_SDK_ROOT` / `JAVA_HOME`. `TAKU_KOTLINC` selects a compiler and `TAKU_KOTLIN_LIB` its lib directory. Without explicit configuration, discovery tries PATH, repository cache `out/toolchains/kotlin-2.3.20/kotlinc`, then Android Studio. Public AOSP **development test signing keys** are fetched as needed into ignored `out/development-signing`, without personal caches. Generated resources contain 104 tokens and source SHA and do not require the external design directory. Source metadata is in `design-token-provenance.json`; no duplicate token JSON is maintained.

The main-reply component catalog also needs Node.js 22.18+ and locked npm dependencies in `system/agent-app` (initially run `npm ci` there). APK builds use `scripts/export-reply-contract.ts` to export the exact schema and prompts from the existing GenUI catalog to ignored `out/reply-assets/native/reply-contract.json`, then package it as `assets/native/reply-contract.json`. ROM asset preparation and immutable source snapshots use the same export. Generated files are untracked.

Outputs are `out/AgentOSAssistant.apk` and `out/task-broker.jar`. The package remains `org.agentos.assistant`, with the existing system UID and Enforcing development-image permission prerequisites. Test keys are unsuitable for production. `install.sh` no longer embeds an experimental emulator: callers must explicitly provide `TAKU_SERIAL` and `TAKU_AVD`, and the script verifies the AVD before pushing. After installation it sets HOME to `org.agentos.agent/org.agentos.agent.home.HomeActivity` and reads it back, never restoring old `CodexHomeActivity` as the main entry. It fails if a matching TakuAgent APK is missing. Neither `install.sh` nor `install-desktop.sh` is a general flashing installer; callers must own the development image.

Runtime interfaces remain `/system_ext/framework/agentos-task-broker.jar`, `/system_ext/etc/init/agentos-codex.rc`, and the original TaskRequests single queue. Device task prompts, results, screens, and Codex authentication are personal data, excluded from source/images. Text input, attachments, and same-turn additions have real-model acceptance. This does not claim ordinary apps automatically receive all platform permissions.

GenUI shared request contracts, main-reply streams, Matter runtime, source adapters, audio sessions, and gateway entries use Kotlin. Non-GenUI native callers remain Java. `scripts/compile-jvm.sh` first lets kotlinc resolve Kotlin and Java source, then javac compiles Java callers, producing JVM 17 bytecode. APK and standalone broker DEX each include Kotlin standard library and licenses. `Android.bp` collects both languages. The APK retains its `agentos-task-broker` static dependency, which supplies shared `UiCardRequest` without duplicate compilation. Standard library packaging follows [Soong configuration](https://android.googlesource.com/platform/build/soong/+/refs/heads/main/java/base.go).

Former package-private implementations use `internal` classes/interfaces. Members used across Java retain ordinary JVM names, static entry points, fields, constructors, and exception declarations. Framework entries and shared contracts remain public. Tools and matters retain existing JSON and persistence contracts. Main-reply native snapshots and `session/reply` events are documented in [session streaming](SESSION_STREAMING.md).

`MainReplyStream` directly parses the main model's `@taku.reply/1` data/component records. `AgentViews` alone owns native display state, validates each record, and publishes the same card with readable text from the same source. Later records do not clear or reorder existing content/nodes. Logical `done` is distinct from native-turn success. Errors/interruption preserve known content; native matters receive action authority only after successful completion. Main replies no longer call formatting, Jev, or layout models, and content callbacks do not read system configuration. Existing conversations receive the new contract through confirmed Harness updates. Structured tasks and memory organization are outside that contract. Agents read the GUI's same snapshot through standard `reply/read`; commands and errors are in the [gateway guide](agent-gateway.md).

Native projection reselects the body source when later tool events establish the message phase. Multiple SDK message aliases retain one readable body carrier while preserving source identities. If authoritative history proves a completed reply's source changed, a higher-revision failure state revokes action authority and preserves the last accepted content. Grouped metrics and their time/details use the frontend's same first-member and expanded-descendant validation rules.

TaskBroker has a fixed **15-minute** per-turn execution budget starting when the native turn starts, including final-result generation. Continued model output, tool calls, and user additions do not extend the deadline. Users may cancel at any time. Timeout interrupts the turn, preserving the existing 10-second stop-confirmation window and touch/process cleanup. Unconfirmed stopping closes the runtime and records failure. Normal completion saves the native final result and terminal task state; already performed external actions are not treated as automatically undone.

### BYOK settings (2026-10-27)

Taku AI → “BYOK · Bring your API key” provides native add/replace/remove flows for fal and OpenRouter. OpenRouter uses on-device Magpie management interfaces, preserving other keys, models, and routes in existing services. Removing a service's only key also removes the service, as explained by the dialog. Adding a key does not change the current assistant connection.

At this stage fal only stores credentials; realtime audio routing is not connected, and the page states that limit. Credentials reside in root-private `/data/local/agentos/ai/credentials/` (directory 0700, files 0600), without host-environment imports. The native management channel permits only root/system UID. Readback returns service IDs and masks, never full keys. Key editors do not save contents in Activity state.

Development-emulator acceptance: build the assistant, start Magpie, enable ADB root, then run `TAKU_SERIAL=<development-emulator-serial> bash system/assistant/test-byok-device.sh`. Temporary synthetic keys check persistence, permissions, redaction, Magpie add/replace/delete, and preservation of existing configuration. Tests clean up their configuration and make no model-generation requests. Successful storage does not verify upstream authentication or billing.

Taku AI's System default models section provides a fal voice-model selector. Current candidates retain Kotoba STS (default) and Grok Voice from the legacy realtime translation path. Without a saved fal key the row is disabled. Returning from BYOK rereads state. Selection persists in private `fal-model.json`. Replacing/removing the key preserves the preference, but removal disables the selector; the server also rejects edits without a key. This setting currently stores only a preference; realtime voice integration remains pending.

## Shared audio module

The composer microphone and completed-reply reading now use the Kotlin [Audio Engine](../audio-engine/README.md). Build that module before the assistant (the full Android build entry includes it). Native realtime retains an internal resource lease while its capture/playback migration is pending. Taku AI exposes local reading voice/speed and read-only audio status. Device-direct fal media adapters are experimental; installed profile/configuration metadata does not certify the selected app or cloud connection. Continuous conversation defaults to half-duplex; long-press its button for the explicitly selected AEC-backed interruption experiment. See the module documentation for scope and pending device acceptance.
