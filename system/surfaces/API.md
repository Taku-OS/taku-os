# Calling Taku system surfaces

SDK development version 0.3 / wire protocol v2, Android API 36+. Provides hints, choices, results, and user-action callbacks. Callers own condition recognition, background processing, artifact storage, and detail pages. The component has no model dependency.

## Integration

Install host `TakuSurfaces.apk` and grant system overlay authorization. Calling apps must share the host's signing certificate (the platform certificate in a system image) and declare:

```xml
<uses-permission android:name="org.agentos.permission.PUBLISH_SURFACES"/>
<queries><package android:name="org.agentos.surfaces"/></queries>
```

System Soong modules add `static_libs: ["taku-surfaces-client"]`. Other Android projects can depend locally on `out/taku-surfaces-client.jar`, generated by `bash system/surfaces/build.sh`. It contains shared contracts, codecs, and the client, excluding host windows, business execution, and test previews. Use Java 17+ and minSdk 36.

See [SurfaceConsumer](tests/consumer/SurfaceConsumer.java) for a complete consumer; build tests compile it using only the exported JAR.

```java
import org.agentos.surfaces.SurfaceSpec;
import org.agentos.surfaces.client.SurfaceClient;

client = new SurfaceClient(context, listener);
client.connect();
// Publish in listener.onConnected(); all SDK calls and callbacks run on the main thread.
```

An Activity or Service can own the client, which uses application context. The caller owns connection lifecycle. `close()` removes that connection's items and unbinds. Do not close merely because an Activity moves to the background if callbacks are still needed. Process death cleans up automatically; background process survival is not guaranteed.

`connect()` throws if binding is unavailable or signing permission does not match. Protocol rejection of a connected request returns an `error` event. There is no hidden retry or offline queue.

## Three call types

```java
// 1. Compact by default; tapping the body returns accept, while the arrow can still expand.
client.showHint("weekend-prompt", 1, "Review your weekend plans?", "Tap to confirm",
    new SurfaceSpec.Action("accept", "View plans", true));

// 2. Expanded by default; button taps return caller-defined option IDs.
client.showChoice("meeting-time", 1, "Choose a suitable time", "Select a time", List.of(
    new SurfaceSpec.Action("sat", "Saturday 18:30", true),
    new SurfaceSpec.Action("sun", "Sunday 19:00", false)));

// 3. Compact by default; tapping returns open-details and the unchanged artifact reference.
client.showResult("weekend-result", 1, "Weekend resources are ready", "View resources",
    new SurfaceSpec.ArtifactRef("my-app:weekend-guide", "text/markdown", "Weekend ideas.md"));
```

All three convenience methods default to bottom placement and a five-minute TTL. After the user drags, saved user position takes precedence. Publications and updates use increasing `revision` per ID, replacing older content. The most recently published item becomes current. Customize placement, initial state, lifetime, and fields with the same factories and immutable configuration:

```java
client.publish(SurfaceSpec.choice("meeting-time", 2, "Choose a new time", "", options)
    .withPlacement("top")
    .withInitialState("compact")
    .withTtlMs(60000)
    .withBlocks(List.of(new SurfaceSpec.Block("field", "Location", "West Lake · Lakeside"))));

client.dismiss("meeting-time");
```

`initialState` applies when switching items or receiving a new revision. Background refreshes and configuration changes do not repeatedly expand a current revision the user has collapsed. Choices cannot bind the whole capsule to one option, preventing selection before options are displayed.

## Structured confirmation

Use `choice` with native blocks when users must review content before continuing. Host 0.3.0 adds `fact` and `notice` using existing `type/label/text`, without new request fields or callback protocol changes.

| Block type | Purpose | Presentation |
| --- | --- | --- |
| `text` | General explanation | Full body text; `label` may be empty |
| `field` | Key/value information such as names and addresses | Label beside value, stacking for large fonts or narrow screens |
| `fact` | Short fields such as dates, times, and counts | Label above value; consecutive facts wrap according to measured text width |
| `notice` | Conditions or notes to review before submission | Label and full body in an orange container |

Labels must be nonempty except for `text`. The host preserves producer text without guessing field meaning or filling business values. A generic calendar confirmation example:

```java
client.publish(SurfaceSpec.choice("review-event", 1, "Create this event?", "Product review · Meeting room A", List.of(
    new SurfaceSpec.Action("confirm", "Create event", true),
    new SurfaceSpec.Action("modify", "Edit details", false),
    new SurfaceSpec.Action("cancel", "Cancel", false)))
    .withBlocks(List.of(
        new SurfaceSpec.Block("fact", "Date", "October 26, 2026"),
        new SurfaceSpec.Block("fact", "Time", "20:00"),
        new SurfaceSpec.Block("fact", "Duration", "30 minutes"),
        new SurfaceSpec.Block("notice", "Invitees", "The 3 selected participants will be invited."))));
```

The primary action occupies a full row. Other actions follow their content widths and wrap as needed. Titles, bodies, fields, and buttons preserve critical text without truncation; large content or an open keyboard allows scrolling. Callers execute subsequent actions only after `confirm`. Important edits should increase `revision` and request confirmation again. Closing only produces `dismissed`, never consent. Older hosts reject unknown block types; do not silently discard notices and proceed. Producers own localization and business decisions. Only an explicit action callback confirms the displayed revision.

`placement` is the default when no user position is saved. Users may drag the capsule or expanded card header, and the host saves position on release. Different callers, items, and expansion states share this preference; callers neither overwrite nor read coordinates. Long-press the capsule/card header and choose “Restore default position” to reapply the current content's `placement`. Position preferences are separate from temporary content and persist only normalized coordinates. Process restart preserves position without replaying old content. Rotation and keyboard avoidance neither rewrite coordinates nor generate business events.

## Callbacks

```java
@Override public void onAction(SurfaceClient.ActionEvent event) {
    // event.id() and event.revision() identify the displayed content.
    // event.actionId() is a producer action ID: accept / sat / sun / open-details, etc.
    // event.artifact() is null for hints and choices.
    if (event.artifact() != null) {
        String ref = event.artifact().ref();
        String mediaType = event.artifact().mediaType();
        String title = event.artifact().title();
        // Route to the caller's own detail page; this callback does not mean it has opened.
    }
}

@Override public void onEvent(String type, String id, long revision, String value) {
    // published / action / dismissed / withdrawn / removed / expired / error / disconnected
    // Generic action callbacks remain, with the action ID in value.
    // Handle business logic in either the generic or typed callback, not both.
}
```

The existing lifecycle contract remains: each revision accepts one action. To reopen actions, including reopening the same result, publish a higher revision. After a callback, `dismiss(id)` removes the surface, or a new revision updates it. User dismissal only withdraws the display; it does not cancel caller work.

## Wire protocol

Explicitly bind `org.agentos.surfaces/org.agentos.surfaces.SurfaceService`. Requests include `replyTo`; `what=1` carries JSON in `Bundle.payload`, `what=2` removes, and `what=3` closes the connection. Full specifications: [v1](../../spec/system-surface.schema.json), [v2](../../spec/system-surface-v2.schema.json). Typed SDK calls send v2; original `publish(String)` and v1 input remain supported.

```json
{
  "version": 2,
  "id": "weekend-result",
  "revision": 1,
  "kind": "result",
  "placement": "bottom",
  "initialState": "compact",
  "tapActionId": "open-details",
  "title": "Weekend resources are ready",
  "summary": "View resources",
  "blocks": [],
  "actions": [{"id": "open-details", "label": "View details", "primary": true}],
  "artifact": {"ref": "my-app:weekend-guide", "mediaType": "text/markdown", "title": "Weekend ideas.md"},
  "ttlMs": 300000
}
```

An empty `tapActionId` makes capsule taps only expand. A nonempty value must match an existing action in the current `hint/result`. `artifact` may be empty; nonempty artifacts are allowed only for `result`. It contains the caller's reference and display metadata, not file contents. The host neither resolves references, reads files, automatically opens links, nor replaces Android's background Activity launch rules.

All callbacks use `what=100` and retain Bundle `type/id/revision/value`. Artifact-bearing `action` adds strings `artifactRef/artifactMediaType/artifactTitle`; other events omit them. Old and new clients can ignore unused callback fields. v1 allows no new request fields. New hosts validate v2 fields; old hosts return unsupported-protocol errors without hidden downgrade.

## Boundaries and verification

Limits: 8 text/field blocks, 3 options, 8 simultaneous items, and lifetime from 1 second to 30 minutes. Temporary content stays in memory, hides while locked, restores unexpired items after unlock, and clears when the connection/process ends. Callers may persist artifact references, but the surface component supplies no result inbox.

Build and check:

```sh
bash system/surfaces/test.sh
bash system/surfaces/test-wire-host.sh
bash system/surfaces/build.sh --demo --tests
```

`--tests` additionally builds real Android JSON codec tests and compiles an independent consumer using only the exported SDK JAR. Test APKs, example producer, and SDK JAR remain in ignored `out/`, excluded from ROM. Device verification must explicitly identify a test serial and retain APK hashes, callbacks, and real screenshots. These do not constitute full-ROM or physical-device acceptance.

After explicitly installing all three built APKs on a dedicated test device and granting host overlay permission, run `tests/verify-device.py --serial <actual-device-serial> --out <ignored-output-directory>`. It first verifies installed APK hashes, then Android codecs, all three call types and callbacks, v1 compatibility, revision updates, and keyboard avoidance. It neither installs apps nor changes system permissions. The system clock is the default other foreground app; override with `--foreground`. It operates the independent preview and stops the preview process when finished.

Ordinary regression requires restoring the default position first. Additional `--position` is for disposable emulators only. It changes/resets preferences through actual dragging and the long-press menu, then verifies service restart, rotation, and recovery after keyboard closure. It rejects physical devices.
