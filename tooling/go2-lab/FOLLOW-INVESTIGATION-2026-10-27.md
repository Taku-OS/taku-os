# Go2 PRO 自动跟随：官方依据、离线实验与实机验证步骤

调查日期：2026-10-27。设备背景：用户的 Go2 PRO，已通过 Mac + Taku Phone 开发模拟器验证点云接收与四方向手动微动。用户在本轮确认拥有小型单摇杆伴随遥控器；最近一次明确的机器狗状态仍是关机。本轮没有连接机器狗、启动摄像头或发送运动、跟随开关、模式切换。

## 结论与适用范围

| 路线 | 判断 | 目前缺少什么 |
| --- | --- | --- |
| PRO + 宇树 UWB 伴随遥控器/标签 | 官方已有 ISS2.0 自动伴随功能，用户已确认有小型伴随遥控器 | 核对配件是否匹配；验证本机固件和真实行为 |
| 只有 PRO + Mac + Taku Phone 模拟器，想直接开启同一个官方功能 | 不能用普通 Wi-Fi 或模拟器代替 UWB 标签；软件开关不能补出标签的位置 | 兼容的真实标签；或改走视觉跟随 |
| 原装狗摄像头 + Mac 视觉跟随 | 技术上可开发，本机离线人体检测算力实验通过 | 真实图传、持续目标锁定、可靠测距、感知时序、控制与停止验证 |
| Taku Phone 管理官方跟随 | 有接口依据，仍是待验证接入方案 | PRO 的 WebRTC 是否转发 UWB 查询/设置、控制权互斥、停止与状态回读 |
| 当前已安装的 Taku 机器狗应用 | 具有点云、状态、手动微动、避障模拟基础 | 尚未实现实机视频跟随；没有可交付的“自动跟随”按钮 |

这里的“官方支持”是型号功能证据；“你的这台狗已经在跟随”必须由实机状态和现场动作共同证明。避障服务此前返回错误，不能推出 PRO 没有跟随功能；支持跟随也不能推出当前已经启用避障。

## 一、官方原生跟随到底跟什么

宇树 [Go2 官方配置页](https://www.unitree.com/cn/go2/) 列出 PRO 支持 ISS2.0 与无线矢量定位。官方 [Go2 隐私政策的自动跟随条目](https://marketing.unitree.com/go2/docPrivacy.html) 明确描述 UWB 定位和佩戴宇树跟随标签。该政策更新于 2023-07-14，可证明机制，不能据此推断今天 App 菜单的位置。

因此，该路线跟踪的是佩戴者身上的定位标签，不能理解成已经用摄像头认出“主人”。Mac 负责 Wi-Fi 通信与计算，Android 模拟器负责界面，都不会产生这个标签需要的无线定位信号。[Android UWB 文档](https://developer.android.com/develop/connectivity/uwb) 同样要求实际硬件及兼容会话；即使某部实体手机有 UWB，也不能据此断言它兼容宇树标签协议。

找到标签后，官方伴随可以由机器人与标签完成，不必依赖这台 Mac 持续传图计算。视觉跟随则需要 Mac 持续在线，移动范围受本地网络覆盖影响；目前的 Taku Phone 是 Mac 上的模拟器，并不是独立随身计算设备。

### 配件确认：用户已有小型伴随遥控器

核对现有配件的外观：可夹腰带，有一个摇杆、M/P 键、侧面的 L1/L2 键，与大型双摇杆遥控器不同。官方主说明书的装箱图将其放在箱盖内衬中；实际附带配置仍以购买清单为准。[官方装箱图](https://doc-cdn.unitree.com/static/2026/6/4/d8a4dd53f1924eb0bf41eee07aad22e5_2482x3509.png)、[伴随遥控器外观](https://doc-cdn.unitree.com/static/2024/6/5/6d4d5395a4f14bb5a52ef2d5a471dfb6_2481x3508.png)。

用户已回答“有这种小遥控器”，因此优先验证现有配件，不需要先购买其他硬件或开发视觉跟随。当前未验证其电量、绑定和固件适配；如启动后无响应，应向原销售方确认该配件与本机的匹配及绑定方法。主说明书中大型遥控器的对码步骤不能直接套用到伴随遥控器。

### 现有配件的具体验证动作

以下是下一次现场验证流程，本轮没有执行。先确认遥控器电量、匹配情况和停止操作可用，选择平整开阔场地；Mac/Taku 保持断开，退出官方 App 的控制会话。不要同时操作两个控制端。

1. 把伴随遥控器夹在右侧腰带外面，人站在狗的左侧，身体与狗同向；位置依据官方示意图。狗按正常开机流程站稳。
2. 短按遥控器电源，等指示灯稳定。此时是摇杆模式。
3. 需要原生避障时，**连续短按 L2 两次（双击）**。官方文档把它列为避障开启；L2 单次短按是关闭。按键是开启请求，仍须在后续受控测试中确认效果。
4. **快速短按 M 两次**进入慢速伴随。先保持人不走，再缓慢走很短一段、停下，观察狗是否跟随和停下。
5. **短按 M 一次**退出伴随回到摇杆模式，现场确认狗实际停稳。首次测试不要再次双击 M，以免切入快速伴随。

依据：[伴随遥控器使用手册](https://marketing.unitree.com/article/zh/Go2/Companion_Remote_Control.html)，尤其[操作页原图](https://doc-cdn.unitree.com/static/2024/6/5/838bb394d61d4889a0be7ddb6bf0347f_2481x3508.png)。

重要限制：官方慢速档最大 1.5 m/s、快速档最大 3 m/s，不能当成我们已测的 0.08 m/s 微动。图中标注 0.8 m，而同页通用注意事项要求人与狗保持至少 2 m，这两处不能拼成一个确定的可配置跟随距离；首次实测前应结合本机说明/官方确认，不承诺按 M 就会保持 2 m。拨动摇杆也能退出跟随，但可能转为手动运动，因此不能把“随便拨杆”当成无条件停止。

主说明书用紫色常亮表示伴随模式；这只是模式线索，不能单独证明避障有效。[指示灯说明](https://doc-cdn.unitree.com/static/2026/6/4/f0b698784ac945bb9dd75e2a29a55af3_2481x3509.png)。本轮未查到明确适用于这台 Go2 固件的标签丢失停止时限或自动恢复规则，不对此作保证。

## 二、Mac 能查什么，能否从 Taku 开启

官方 SDK2 中有独立的 `UtrackClient`：

| 服务/API | 官方定义 | 这次工具处理 |
| --- | --- | --- |
| `uwbswitch` / 1002 | 读取跟随开关 | 允许，只在 `--follow` 模式查询 |
| `uwbswitch` / 1003 | 查询是否 tracking | 允许，原样记录；响应结构尚未在本机验证 |
| `uwbswitch` / 1001 | 设置开关 | **拒绝发送** |
| `rt/uwbstate` | UWB 状态候选主题 | 被动订阅；是否发布、字段单位和有效性待实机核验 |

依据：[utrack_api.hpp](https://github.com/unitreerobotics/unitree_sdk2/blob/main/include/unitree/robot/go2/utrack/utrack_api.hpp)、[utrack_client.hpp](https://github.com/unitreerobotics/unitree_sdk2/blob/main/include/unitree/robot/go2/utrack/utrack_client.hpp)、[UwbState 定义](https://github.com/unitreerobotics/unitree_sdk2/blob/main/include/unitree/idl/go2/UwbState_.hpp)。状态定义包含距离/方位估计、标签与基站姿态、错误状态等；有这些字段不代表当前数据有效。

1002 的官方 `enable` 是整数，工具仅将 0/1 或严格布尔值解释为开关，其他内容记为未知。1003 的名字不足以确定返回 JSON 结构，因此没有猜测解析。扩展查询中的 API 1 是服务协议版本查询，不是机器狗固件版本。

这些定义证明存在调查入口，不能证明 PRO 对外开放官方 DDS SDK，也不能证明相同消息一定能通过 PRO 的 WebRTC 转发。安装 SDK 不会自动开通权限、生成标签信号或解决控制权问题。

### 下一次开机：先只读采集

1. 先用官方方法退出跟随，确认狗静止。关闭其他控制会话，包括现有 Mac 桥接。诊断工具不会替其他控制器停止运动。
2. 从热点设备列表重新核对狗的 IPv4 地址。`78:22:88:b4:b4:f6` 是 MAC 地址，不能传给 `--robot-ip`；历史 IP 也不能直接当作当前地址。
3. 先运行离线计划，完全不连接：

   ```sh
   cd $TAKU_OS_ROOT
   python3 tooling/go2-lab/diagnose-readonly.py --follow --extended
   ```

4. 只有狗在线、地址已验证且现场有人时，才执行以下模板；把 `VERIFIED_DOG_IPV4` 换成实际 IP，输出文件必须尚不存在：

   ```sh
   "$HOME/Library/Caches/taku-go2/venv/bin/python" \
     tooling/go2-lab/diagnose-readonly.py \
     --connect --robot-ip VERIFIED_DOG_IPV4 --follow --extended --seconds 10 \
     --output /tmp/go2-follow-readonly-NEW.jsonl
   ```

5. 工具自动结束会话；检查每个 RPC 的状态码、响应关联、UWB 更新次数与接收时间。没有数据、超时或错误统一视为不能下结论，不解释成“没有这项能力”。

判读顺序：开关值 → tracking 原始回包 → 标签相关数据是否持续新鲜、是否随佩戴者移动合理变化 → 现场实际跟随/停止。四者不能互相替代。标签接近/远离的纯观察实验必须先确认跟随关闭；如发现狗自行移动，先通过现场控制停止，不继续做数据实验。

若读接口可用，Taku 可先加入“标签是否有数据、跟随开关、数据年龄”的状态显示。设置功能还需另行验证 1001 的本机兼容性、开启前条件、失败回读、关闭行为及控制权；当前应用没有开放它。官方遥控器、App、Taku 自动控制之间应显式切换，禁止原生伴随与 Taku 普通 Move 同时发命令。

## 三、无标签视觉跟随：可行，但还需要哪些环节

建议链路：

```text
狗原装摄像头 → WebRTC 视频 → Mac 本地人体检测/持续目标跟踪
                                     ↓
                       用户在 Taku 画面中选定目标
                                     ↓
                    目标相对方向 + 可靠距离 + 数据新鲜度
                                     ↓
                  障碍/控制权/停止检查 → 受限运动控制
```

现有驱动具备接收视频 track 的接口，但当前 Taku 桥接尚未接入图传，且只读白名单有意禁止开启媒体。因此下一步应新增明确的“只看视频”入口，不修改现有只读诊断的权限。

关键缺口与验收方法：

| 环节 | 需要实现的行为 | 必须验证的情况 |
| --- | --- | --- |
| 图传 | 保存接收时间/帧序，处理最新帧，显式报告丢帧 | 人在画面内移动；冻结画面、断网、解码异常后禁止继续决策 |
| 目标锁定 | 用户选人，关联连续帧中的同一目标 | 第二个人进入、两人交叉、遮挡；不自动改跟别人 |
| 距离 | 标定摄像头与雷达关系，或先验证有误差边界的测距法 | 远近、侧身、蹲下、局部遮挡；不能把像素框面积直接当米 |
| 点云融合 | 配准坐标、对齐时间，在人体视锥里关联有效测距点 | 背景墙点、地面点、体素降采样、雷达盲区及错误配准 |
| 控制 | 有界速度、单一控制源、数据失效撤销授权、停止确认 | 丢目标/数据过期/网络卡顿/服务崩溃；停止失败锁定后续动作 |
| 避障 | 验证机载避障对所用命令通道有效，或外部保守拦截 | 人走到纸箱后面时不能直线追穿纸箱；必要时停下等待 |

第一版宜限定为：一个明确选定的人、平整开阔地、狗前方可见目标、低速前跟。目标消失时停止并等待重新选择，不自动转圈寻找，不默认自动后退，也不承诺绕过遮挡物继续追踪。自动绕路需要额外局部规划与验证。

这里仍可使用原装摄像头和雷达，不必先购买外置深度摄像头，但相机/雷达标定和关联能否达到要求需实测；如果缺乏可用标定或目标点不足，就不能靠猜测距离开放运动。

我们之前的 0.35 秒是一次运动脉冲时长，不是传感器更新周期，也不是系统延迟。已有四方向按钮证明基本命令能起效，不能直接拼成可靠连续跟随。低速会降低延迟期间的行进距离，但仍要测摄像头/点云延迟、控制周期、抖动、停止时间与制动距离。

大模型可以解释“跟着我/停止”并请求切换任务；持续看人、测距和制动应由本地明确控制逻辑完成，避免每帧等待云端对话返回。

## 四、本轮实际实验结果

### 1. 这台 Mac 能否承担人体检测

本机 Apple M4 Pro、24 GiB 内存。使用 macOS Apple Vision 的 `VNDetectHumanRectanglesRequest` revision 2，对公开的公交车街景样图生成 33 个微小位移裁剪，前 3 次预热、后 30 次计时。输入原图 810×1080，处理裁剪 778×1048，置信度门槛 0.5。

| 指标 | 本轮结果 |
| --- | --- |
| 单次检测耗时中位数 | 3.902 ms |
| P95 | 4.315 ms |
| 最大值 | 4.503 ms |
| 本进程首次请求 | 75.105 ms；系统/模型此前可能已经预热，不是冷机启动值 |
| 人体框数量 | 20 次返回 2 个，10 次返回 3 个 |
| 每帧选择最高置信度框 | 在左/中两个人所在的空间区间之间切换 7 次 |

这证明在这个样本上，本机人体检测的计算耗时较低；也说明“每帧跟最高置信度的人”不具备目标稳定性。7 次是人工核对原图后按框中心所在区间统计，并非标准身份跟踪数据集的 ID-switch 指标。

没有测真实狗视频、端到端帧龄、身份跟踪准确率、测距、避障或机械响应。不能用 1000/3.902 宣称整机跟随能达到某个帧率，也不能由一张图推出复杂场景识别效果。

复现工具：[benchmark-human-detection.swift](benchmark-human-detection.swift)。它只读取本地图像，没有相机、网络或机器人接口：

```sh
swift tooling/go2-lab/benchmark-human-detection.swift /absolute/path/to/test-image.jpg
```

素材来源：[Ultralytics 公共示例 bus.jpg](https://github.com/ultralytics/ultralytics/blob/main/ultralytics/assets/bus.jpg)；图像 SHA-256 为 `c02019c4979c191eb739ddd944445ef408dad5679acab6fd520ef9d434bfbc63`。使用的是 Apple 检测器，没有运行该仓库的 YOLO 模型。素材本体只保留在本机 ignored 输出目录，报告记录来源与哈希。

### 2. 社区“现成自动跟随”代码能不能直接运行

检查了实际源码，未在机器人上执行这些项目。

- [orisharabi/unitree-go2-follow-system](https://github.com/orisharabi/unitree-go2-follow-system)：主要 FOLLOW 路径仍依赖 UWB，不能解决“没有标签”的问题；采用官方 DDS 控制链路，不能直接证明 PRO WebRTC 兼容。默认控制器会给出 0.9 m/s 指令，初始化还包含控制权和避障写入，不适合直接接到当前机器狗上试运行。
- [amznhacker 的视觉跟随文件](https://github.com/amznhacker/go2_webrtc_connect/blob/main/go2_webrtc_driver/vision/follow_behavior.py)：实际取视频帧函数仍返回 `None`。对其[控制器](https://github.com/amznhacker/go2_webrtc_connect/blob/main/go2_webrtc_driver/vision/object_tracker.py)做隔离实验：50×100、100×200、200×400 的居中目标框均计算出 -0.15 的后退指令，因为面积阈值固定为 100/400；它不是经过标定的米制距离。零速度建议传给运动函数时，假传输记录到 0 条消息，不能用这个路径证明已发送停止。这是函数行为测试，不是实机后退或停止距离测试。
- [DimOs_Windows](https://github.com/BeBecpp/DimOs_Windows) 有目标锁定等可参考结构，但项目自己的硬件验证门槛说明仍有待验证项，不能作为本机已经能跟随的证据。

隔离实验只对两个固定哈希的已审查源码片段运行：纯数值控制类，以及使用假传输的单个函数；没有导入社区模块、初始化驱动或连接狗。[复现脚本](audit-community-follow.py)会拒绝任何不同内容。实验快照在本机 `out/go2-lab/follow-research-2026-10-27/`，两文件 Git blob 分别为 `8521575590a591c55f056707c2a87c2313a72ae3`（object_tracker）与 `37bc4392fc8e8f0474cc73048adfe0aef8a9175e`（follow_behavior）。

不要混淆其他接口名称：社区 `LeadFollow` 对应牵引类步态且不同模式编号不同，不是已验证的 UWB 开关；`TrajectoryFollow` 是轨迹跟踪，不提供人的检测，而且[官方 ROS2 变更记录](https://github.com/unitreerobotics/unitree_ros2/blob/master/CHANGELOG.md)在 v0.2.0 中注明移除该接口的支持。名称里有 Follow，不等于可直接用于跟人。

### 3. 诊断工具验证

新增 `--follow`；默认运行与带 `--follow` 的运行都必须显式加 `--connect` 才可能联网。发送白名单禁止 UWB 设置、普通运动、模式写入和路径跟踪；回复严格关联服务、API、请求 ID 与状态码，未知值不降级成 false。

`npm run check:go2` 通过：36 项 Python 测试与 5 个 JavaScript 语法检查。跟随部分包括 12 项诊断测试中的开关类型、只读白名单、离线 CLI、假 SDK 完整会话与错误回复处理。测试使用替身，不证明真实 PRO 的 UWB 接口可用。

完整离线结果：[follow-offline-2026-10-27.json](evidence/follow-offline-2026-10-27.json)。

## 五、下一步按什么顺序做

1. **用户已确认有小型伴随遥控器，先验证官方跟随。** 按上述实机步骤核对电量、匹配与退出；无需先开发视觉控制。
2. **开机只读调查。** 获取 App/固件版本，运行上述 UWB 诊断；没有匹配回包时保持未知，不尝试盲扫写 API。
3. **Taku 只观察。** 如果走视觉路线，先接收视频，在 Taku 中选人、画框、显示目标持续时间和数据帧龄，运动始终锁定。采集站立、走动、交叉、遮挡、画面冻结样本。
4. **离线与影子运行。** 用真实录制数据计算“如果允许运动会给什么指令”，但不发送；测目标丢失、点云过期、坐标不匹配、网络中断后是否撤销决策。模拟只能检验软件逻辑，不冒充真实制动和避障。
5. **现场低速闭环。** 前四步证据满足后，再单独验证限速、短时授权、停止响应、纸箱拦截；最后才测试跟随人。使用现有微动速度作为初始上限候选，不能由此保证跟得上正常步行。
