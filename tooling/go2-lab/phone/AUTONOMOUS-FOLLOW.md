# Pixel 自动人物跟随

在已有视觉跟踪页上接入运动闭环。Taku AI 把“跟随前面的人，保持初始距离”解析为单个 `follow_start` 操作；页面发送本地人体模型的观测，手机 Python 控制器调用既有 Motion 接口。文字模型不逐帧规划、不直接发送运动 RPC。明确“只观察，不移动”仍使用 `show_follow`。系统模型不可达时，对少量完整匹配的跟随/停止口令使用本地兜底，原生状态栏明确显示“本地指令”；问句、条件句和其他描述不会被宽泛关键词自动启动。

保持距离以首次选中的身体分段画面尺度为参考，**不是精确米数或深度相机测距**。多人时点击人物；不保证理解黑裤子黑鞋子的语义，也不做身份识别。第一版使用相对距离约 ±12% 的保持区间，横向中心偏移超过 10% 时先转向；前进 0.08–0.20 m/s、后退 0.08 m/s、转向 0.15–0.40 rad/s。每段最多 0.30 秒，按新观测继续调整；会有分段停止，不承诺连续平滑步态。

控制器只接受当前会话令牌和摄像服务近期实际收到的帧标识，至少 3 个有效连续观测后才发动作。观测超过 0.7 秒、人物丢失或方向变化时打断当前段；每段仍要求 StopMove 回执。后台退出、人工接管、停止、断开连接、2.5 秒无观测或 5 分钟会话到期均撤销控制。连接恢复不会自动重新启动运动；重新输入跟随指令。重新选人会建立新的初始距离。

启动要求真实连接、实时视频、正常运动模式与新鲜的站立姿态。模型请求只产生 20 秒有效的一次性启动许可；离线启动失败不会排队等狗上线后执行。App 和服务重启不恢复运动。停止后恢复用户原有速度设置。

当前没有接入行走路径规划、地形判断或前后方自动避障。已有导航/避障控制器与本功能互斥，避免同时控制。仅完成了模拟运动、浏览器观测链路和手机离线入口验证；真实左右方向、距离反馈、人体遮挡、低速步态、停止响应及热点延迟必须在空旷平地逐项验收。

## 接口

- `GET /api/follow/state`：状态，不包含令牌。
- `POST /api/follow/start {requestId}`：消费 AI 请求许可，返回会话令牌。
- `POST /api/follow/observe {token,frameKey,target}`：`target` 为 `{x,ratio,id}` 或 `null`；后者表示暂时无法确认人物。
- `POST /api/follow/stop {token}`：只停止该会话；空对象显式撤销当前会话与待执行许可。

HTTP 沿用 loopback Host/Origin 限制。此开发版不具备 Android 应用之间的强身份隔离；会话令牌与帧校验用于防止过期请求继续控制，不代表已完成生产权限隔离。

## 无硬件验证

- `tests/go2-follow-control.test.py`：SimBridge 的运动与停止、速度、目标丢失/重获、过期帧、错误令牌、停止失败、断线、人工接管。
- `tests/go2-follow-http.test.py`：独立模拟进程验证 AI 计划、HTTP 契约、离线不可排队启动。
- `tests/go2-follow-drive.test.cjs`：浏览器样本验证原页面到控制接口、距离变化、丢失/找回、停止；不连接真实设备。
- 原有 `go2-motion`、`go2-camera`、`go2-assistant`、`go2-follow-person`、`go2-follow-recovery` 回归检查。
