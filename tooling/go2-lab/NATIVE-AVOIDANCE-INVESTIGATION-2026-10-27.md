# Go2 PRO 原生避障：调查结果与下一次实机操作方案

调查日期：2026-10-27。对象是用户现有 Go2 PRO、Mac 和 Taku Phone 开发模拟器。本轮狗已关机；没有连接狗、发送开关、切换模式或移动。以下严格区分官方资料、历史实测、静态代码证据与待验证项目。

后续自动跟随调查中，用户已确认拥有小型伴随遥控器。因此下文路径 C 的“连续短按两次 L2”现在是已有配件可尝试的官方避障入口，仍需确认匹配与本机效果。跟随操作、只读 UWB 诊断及控制权限制见 [自动跟随调查](FOLLOW-INVESTIGATION-2026-10-27.md)。

## 1. 先回答三个核心问题

**PRO 有官方原生避障功能。** 官网参数表和当前官网提供的《Go2 使用手册》V4.3 均列出 PRO 的探物避障。PRO 不提供与 EDU 相同的官方二次开发支持，不等于没有机载避障。[官方参数](https://www.unitree.com/go2/)、[手册第4页](https://doc-cdn.unitree.com/static/2026/6/4/f0b698784ac945bb9dd75e2a29a55af3_2481x3509.png)。

**已经找到官方开启方法，目前无需新增配件的优先候选是机身语音。** 手册给出的顺序为：说“你好笨笨”，等狗回答“我在”，再说“开启避障”，预期回答“已经打开避障模式”。这由狗自身的语音模块响应，不是 Mac 扬声器。官网还明确列出离线语音交互/指令；该路线不应先以手机有外网、云注册成功或 Mac 的 1001 调用成功为必要条件。不过用户这台机器的具体固件、地区和唤醒词尚未核对。[语音操作第10页](https://doc-cdn.unitree.com/static/2026/6/4/ba93908950fc4ef887de1e68d27b042d_2481x3509.png)、[官网中文参数及语音脚注](https://www.unitree.com/cn/go2/)。

**还没有证明这台狗经 Taku Phone 发出的移动指令受到原生避障保护。** 之前的 `3203` 只涉及一个服务的一个开启入口。必须分别验证当前开关、运动模式、控制通道和实际行为，不能从灯亮、点云显示或接口返回成功直接跳到“已安全接入”。

## 3. 四件容易混淆的事

### 3.1 雷达打开，不等于任意运动命令都有避障

用户看到的“关雷达会使避障失效”，说明雷达是相关感知前提；反过来不能推出开雷达后所有控制入口均受保护。点云能画出来也只能证明一条传感数据路径可用。

### 3.2 前向防撞、闪避和导航绕行不是同一个功能

手册的探物避障说明限定为向前方向。因此不能用前向测试通过推断后退、侧移和原地转身都安全；雷达扫描角度广，也不等于算法保证全方向保护。[手册第5页](https://doc-cdn.unitree.com/static/2026/6/4/580526b7d501416299df49d297b8fbbe_2482x3509.png)。

官方双手遥控器手册把“闪避”模式与“避障开/关”分成不同按键项。这证明不能把闪避模式入口、一般防撞开关以及 SDK 中包含 Avoid 的接口全当作同一件事。[遥控器第8页](https://doc-cdn.unitree.com/static/2025/12/22/7b370601b51d4db097b4dc646b153e2d_2481x3509.png)、[第9页](https://doc-cdn.unitree.com/static/2025/12/22/808e7ee4e1f94fb79e12ab1853843169_2481x3509.png)。

用户期望“前进→绕过纸箱→继续去前方”还包含目标方向、可通行空间和局部路径规划。当前找到的官方手册不能保证一条普通前进指令自动完成这一整段行为。

### 3.3 官方 SDK 是客户端，不是把避障算法装进狗的安装器

官方 Python SDK 的避障 client 负责封装参数、发请求和读回结果；真正处理环境和运动的服务在机器上。服务未实现某 API 时，在 Mac 安装更多 SDK 包、换 Python/ROS2，不能自动补出机载服务。官方服务是否能通过固件更新提供，需要匹配具体型号和版本确认。

### 3.4 AI 标签与 SDK 的模式名不宜直接一一对应

官方网页、App 页面标签、运动模式服务返回的 `normal/ai/mcf`，以及灵动/经典等步态，属于不同层级。不能因为 App 写 AI，就假定 `obstacles_avoid` 一定开或一定关；也不能因某示例要求 normal 就把它当作全固件规则。

## 4. 官方开启与识别路径，具体到动作

以下是**下次开机时执行**的方案，本轮没有执行。

### 路径 A：不用 Mac 的离线语音，优先尝试

1. 按正常流程开机，在平整空地等机器完成启动；先不触碰行走摇杆。
2. 记录头部状态指示灯颜色，拍一张当前 App 模式/步态画面。
3. 保持雷达开启。你已找到的雷达开关不需要来回切换做实验。
4. 靠近到正常说话能被收音的位置，清楚说默认唤醒词“你好笨笨”。
5. 等待狗的唤醒应答，再说“开启避障”。记录有无开启应答、灯色有无变化。
6. 没有唤醒应答时，在 App 内查找手册所称的“Go2 语音词条”，以当前设备列出的唤醒词和指令为准；确认声音没有被静音、语音功能可用。当前版本的具体菜单路径尚未核实；若没有该入口，记录页面再定位，不猜按钮。不要把无应答解释为无避障功能。
7. 有应答也先只记为“语音开启入口有确认”，再走状态回读和受控前向测试。

依据是手册第10页。该页没有要求这组词必须通过联网对话，也未说明必须保持 App 连接。现有 APK 还含有不同语音产品的资源，因此不会根据一个静态唤醒词字符串强行改你的配置。

**本步骤不说“向前走”。** 手册把该语音动作描述为解锁后前进约2秒，与此前 0.35秒微动不是同一个约束。

### 路径 B：用头部状态灯交叉核对

按 V4.3 手册第4页：正常启动后的绿色常亮对应默认避障开启；蓝色常亮对应避障关闭。黄灯的续航状态、紫灯的伴随状态有更高显示优先级，因此黄/紫不能单独判定避障是否开启。看的是状态指示灯，不是白色前照灯。

把灯色作为辅助证据。若出现“语音确认开启、蓝灯不变”或“绿灯但 API false”，保留照片和时间，继续核实版本/路径，不能挑一个结果强行宣布成功。

### 路径 C：已有匹配遥控器时才使用

| 遥控器 | 手册中的开启动作 | 使用限制 |
|---|---|---|
| 伴随遥控器 | 连续短按两次 L2 | 单次短按是关闭，不能把两次间隔很长的单击当双击 |
| 双手遥控器 | 单击 X | 依据当前 V2.3 手册；先核对手中遥控器型号/布局 |

来源：[伴随遥控器操作第12页](https://doc-cdn.unitree.com/static/2026/6/4/ed9dc39151844bc18674b68f98f35e97_2482x3509.png)、[双手遥控器第9页](https://doc-cdn.unitree.com/static/2025/12/22/808e7ee4e1f94fb79e12ab1853843169_2481x3509.png)。你目前不必为这轮诊断先买配件。不要把 A 双击进入闪避当成上述普通避障开关。

## 5. Mac 只读诊断工具已经补好

新增 [diagnose-readonly.py](diagnose-readonly.py)、[diagnostic_protocol.py](diagnostic_protocol.py)。它是一次性诊断进程，**不启动 Taku Phone 控制服务**。

### 5.1 默认运行只是离线计划

```sh
cd $TAKU_OS_ROOT
python3 tooling/go2-lab/diagnose-readonly.py
```

默认不导入机器人驱动、不打开连接。已执行并测试。

### 5.2 下次开机后的真实只读采集

先做以下动作：

1. 用 App 保持狗静止，记录当前模式，不点击切换模式。
2. 核实狗的当前 IP。`78:22:88:b4:b4:f6` 是 MAC 地址；以前热点下的 `192.168.5.128` 只是历史 IP，不能直接沿用。AP 和手机热点 STA 不能混用旧地址。
3. 退出官方 App 的机器人连接，并让 Taku Phone 页面断开；避免两个 WebRTC 控制端争用同一台狗。仅“退出页面”是否释放连接应以 App 状态为准。
4. Mac 连到狗当前所在的同一局域网；AP 情况则连狗的热点。确认目标 IP 与这只狗匹配，不扫描猜写入端点。
5. 在 Mac 终端运行下面命令，把 `已核实的狗IP` 替换为实际 IPv4。输出文件必须是新名字。

```sh
cd $TAKU_OS_ROOT
mkdir -p out/go2-lab/diagnostics
"$HOME/Library/Caches/taku-go2/venv/bin/python" \
  tooling/go2-lab/diagnose-readonly.py \
  --connect --robot-ip '已核实的狗IP' \
  --extended --seconds 10 \
  --output out/go2-lab/diagnostics/after-voice-01.jsonl
```

连接握手最多等待40秒，各查询最多3秒，随后被动观察10秒；不无限重试。若新固件要求额外认证，工具只报告失败，不自动登录云端或提取密钥。结束后自行断开，不自动恢复控制桥接。

### 5.3 查询清单及解释

| 内容 | 服务 / API | 结果能说明什么 |
|---|---|---|
| 当前运动模式，前后各一次 | motion_switcher / 1001 | code=0且有效 payload 才可解释模式；否则未知 |
| 避障服务开关，三次 | obstacles_avoid / 1002 | 严格布尔 true/false；不是整机防撞认证 |
| 服务 API 版本（extended） | motion_switcher、obstacles_avoid、sport / 1 | 服务协议版本，不是整机固件版本 |
| 服务列表（extended） | robot_state / 1003 | 官方只读候选；PRO WebRTC是否转发待实机验证 |
| 被动状态 | sportmodestate、lidar_state、robot_pose、servicestate、multiplestate | 有消息可记录；没有消息只能标未知 |

这些只读接口的定义来自官方 [MotionSwitcherClient](https://github.com/unitreerobotics/unitree_sdk2_python/blob/master/unitree_sdk2py/comm/motion_switcher/motion_switcher_client.py)、[RPC Client](https://github.com/unitreerobotics/unitree_sdk2_python/blob/master/unitree_sdk2py/rpc/client.py)、[RobotStateClient](https://github.com/unitreerobotics/unitree_sdk2_python/blob/master/unitree_sdk2py/go2/robot_state/robot_state_client.py)。

日志保留请求编号、服务、API、参数、响应匹配结果、code、回包数据、时间及出站消息计数。认证正文不记录，常见凭据字段过滤；文件不覆盖旧证据。`lastAgeMs` 是消息到达 Mac 的年龄，不能称为传感器到运动控制的总延迟。

该工具主动禁止避障开启/关闭、运动来源接管、运动、停止、模式切换、雷达通断和省流开关。因而它可能收不到需要主动打开流量的雷达状态，这是刻意限制，不是功能不存在的证据。

### 5.4 为什么要补这个工具

离线审计发现，已安装社区驱动的 FutureResolver 仅以 ID 匹配请求，缺少 API/topic 校验；同 ID 的不同服务请求可以被一条响应同时完成，超时取消后晚到响应还有清理问题。纯离线 mock 已复现。

但历史开启脚本是串行的，未启动桥接轮询，**不能因此宣布历史3203是错包**。历史日志缺少请求/响应身份明细，无法事后进一步确认。新工具独立监听回包，校验 ID、API、服务topic、响应类型和状态码，并正确清理超时请求。

离线验证：`python3 tests/go2-diagnostic.test.py`，10个测试通过，包含写入拒绝、错服务/错API/畸形回包、超时晚回包、取消清理、默认无驱动运行、凭据过滤及完整假驱动会话。`npm run check:go2` 的34个Python测试和前端JavaScript语法检查通过；Python编译检查通过。**没有实机执行过新工具。**

现有控制桥接尚未迁移到这个独立的严格关联器。后续开放Taku原生避障控制前，需要一并修正控制桥接的回包校验并回归停止流程；本轮工具不代表已修复所有既有控制路径。

## 6. 把官方能力接进 Taku Phone：可选路径与优先级

### 优先路径：先证实 App 行走避障，再验证同类摇杆通道

社区驱动维护者说明，普通无线控制器输入经 `rt/wirelesscontroller`，开启对应避障服务时会经过过滤；专用 API 移动则需要另一套命令来源设置。[维护者解释，issue #48](https://github.com/legion1581/unitree_webrtc_connect/issues/48)。社区 UI 作者还记录了官方 App 摇杆与该 topic 的关联。[remote-control.md](https://github.com/legion1581/unitree_ui/blob/main/docs/remote-control.md)。

这是值得验证的集成路径，尚不是用户这台 PRO 的成功证明。未来 Taku Phone 可将限定的方向意图发给 Mac，再由 Mac 按已验证的摇杆协议发送，让机载逻辑处理障碍。要先完成：

1. 找出该固件 App 实际使用的通道和模式；社区说明只能作为候选。
2. 在空地校准最小摇杆量对应的真实速度。摇杆 `lx/ly/rx/ry` 是无量纲输入，不能把0.08直接当0.08m/s。
3. 验证中立输入、松手、断连、模式切换时的停止行为和超时。未证实前不能承诺丢包会自动停。
4. 只在前向受控场景验证机载保护；首次不组合转向绕行。
5. 手机明确显示“该控制路径避障待验证/已验证的模式及方向”，状态过期禁止新动作。

当前已有的手动微动走 `sport Move(1008)`，没有被本轮改成摇杆通道，也没有新增“已有原生保护”的承诺。手机仿真成功不能替代这一步。

### 次选路径：专用 obstacles_avoid 服务

官方客户端定义了查询、开关、专用移动、选择 API 命令来源的接口。[ObstaclesAvoidClient](https://github.com/unitreerobotics/unitree_sdk2_python/blob/master/unitree_sdk2py/go2/obstacles_avoid/obstacles_avoid_client.py)。

当前实测只到开启入口被拒绝。若下次获得受支持版本/模式证据，再做单次明确的开启→多次回读。必须先读到 true，再分别验证命令来源与停止；不能在1001失败后用1004接管、1003移动去“碰运气”。

若严格诊断仍显示3203，应带设备版本向官方确认服务支持矩阵，停止重复同一请求。重启电脑、装不同SDK不等于服务就会出现。

### 调查候选：sport FreeAvoid(2048) 与 SwitchAvoidMode(2058)

官方 [SportClient](https://github.com/unitreerobotics/unitree_sdk2_python/blob/master/unitree_sdk2py/go2/sport/sport_client.py) 和 [ROS2更新日志](https://github.com/unitreerobotics/unitree_ros2/blob/master/CHANGELOG.md)确实存在这两个客户端接口。2048接收布尔参数；2058没有显式 enable 参数，不能当作可反复调用的“确保开启”。它们与 `obstacles_avoid/1001` 不是同一个调用。

我没有找到可访问的官方原文确认“FreeAvoid尚未接入”，也没有找到这台 PRO 的服务端兼容保证。官方文档中心本次普通访问受限；查不到不能写成官方已否定。社区库常将 FreeAvoid称为闪避模式，而官方遥控器又把闪避与普通避障开关分开；因此尤其不能按接口名字猜语义、批量试编号。

这两个动作可能影响运动模式或自主反应。本轮没有调用，诊断工具也明确禁止。后续只有在固件含义与退出方式明确后，才列入单独受控实验。

### 若无法使用官方原生路径

仍可做 Mac 点云防撞停车与局部规划，但这是自研功能，不能标成官方避障。当前实际阻碍包括：点云 odom 与运动状态坐标关系未配准、真实姿态未标记 aligned、感知时间和停止延迟未完成实测。

可按“可靠停车→受控单方向绕行→闭环到目标”逐级实现。现有Mac和雷达足以继续研究，不需要先买外置传感器；实际效果受传感盲区、网络和控制延迟约束。不要为了跑通界面直接把 `aligned` 改为 true 或取消保护检查。

## 7. 下一次实机验证表：什么动作，怎样判定

### 第一步：保存版本与基线（不移动）

- Android 系统的 Unitree Go“应用信息”中记录 App 版本。也可在手机已授权 USB 调试时只读查询包版本；那不是狗的固件。

### 第三步：先用官方 App 验证前向防撞

这是下一次现场有明确运动授权、停止手段已确认后的实验，不由本轮脚本自动执行。

1. 选择平整空旷地面，测试区内无人、宠物和台阶。纸箱要稳定、足够宽高且无玻璃/镜面；先用尺或地面标记量距离，不仅靠尚未配准的点云图。
2. 记录当前模式，先在无遮挡方向用最小可控输入验证“能慢走、松手能停、停止入口有效”。不要先朝纸箱测试制动。
3. 把纸箱放到正前方约1.5米，左右保留空间，使用与空地基线相同的小输入短试。记录狗头朝向、箱体位置、实际动作和摇杆输入。
4. 首轮只观察前向接近，不要求自动转弯。每段短试后完全停止并重新观察，不排队连续推进。
5. 预先设人工中止线，首次约1米或更远，且必须大于空地已验证的停止距离加人工反应余量。若未明确减速/停止就人工停止；这不是宇树公布的触发距离，也不是适用于任意速度的保证。到中止线尚未触发只能记“本条件未验证”，不能继续顶向箱体来证明有无功能。
6. 将纸箱移出前方，同样输入再做空地对照。如果有箱时被抑制、移开后恢复，并且现场视频与状态一致，才支持“该模式、该通道、该方向下有效”。重复几次检验一致性，不为证明结论而关闭保护对撞。

**判定规则：** 一直不动可能只是锁定/模式不对；脚步调整不是避障；前方停住可以算前向抑制证据，但不能算绕行成功。绕行成功还需记录箱体侧边通过净距、全身运动范围和最终恢复方向。

## 8. 时间与数据：0.35秒不是传感器周期

0.35秒是我们此前主动设定的一次微动时长。历史短窗口观测约点云7.55Hz、运动状态19.94Hz；这仅说明当时接收频率，不是最坏延迟或安全认证。

已知日志出现点云源时间戳粗粒度、运动状态时间更细的情况。现有代码用本地到达时间判断新鲜度，因此源时间戳粗糙没有直接触发假陈旧；但设备重复旧帧仍可能显得新鲜。不能直接拿两个未确认时钟域的时间戳相减，宣布传感延迟几分钟。

自研停车需要实测总距离预算：从感知到决策/通信的运动距离 + 实际制动距离 + 定位/箱体/机身范围误差余量。减速有帮助，但“速度低”本身不是避障已经可用的证明。原生避障主要在机内处理，Mac点云刷新慢不能单独否定它。
