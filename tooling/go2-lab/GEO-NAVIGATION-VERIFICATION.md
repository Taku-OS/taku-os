# 高德选址到机器狗路线跟随：实现与验收

2026-10-27。代码仓库为 `taku-os`，应用为 Taku Phone 的 `org.taku.go2lab`。设备条件：只有 Go2 PRO 本体，没有外挂定位设备。

## 结论与范围

已实现并验证这条软件链：高德真实搜索／地图点选 → 步行路线 → GCJ-02 与局部 odom 转换 → 滚动雷达地图 → 局部避障路径 → 低速模拟跟随 → 到达或异常停止。页面持续显示摄像头、任务进度和位置；Android CLI 可调用同一个任务控制器，页面按路线几何摘要同步对应地图。

**这不是实机户外自主导航验收。** 测试使用真实高德数据、合成平地／纸箱／摄像头／雷达和运动学模拟狗，不代表真实道路地形。没有连接真实狗，没有发送实机移动或避障开关命令；没有运行模型自主识别道路、过街或规划真实出行的实验。已验证 AI 可用的工具调用链，不把程序测试等同于模型自主决策验证。

## 已补上的模块

| 缺口 | 实现 | 当前限制 |
| --- | --- | --- |
| 狗的位置和朝向 | 读取 sport 位姿，绑定连接／地图代次；输入已知 GCJ-02 位置及罗盘方向，建立地理参考 | 是人工参考加相对里程计，非 GNSS，非经过评估的 SLAM 全局定位 |
| 高德与局部坐标转换 | 北 0°、东 90°，结合 odom yaw 建立旋转和平移；支持双向投影 | 真实 sport 与 LiDAR 的关系尚未现场配准；服务仍阻止实机自主执行 |
| 高德地图显示和点选 | 固定中心和缩放级别的静态地图，反投影点选终点，叠加当前地理位置／朝向 | 不是可拖动缩放的 JS API 地图；总览绘图最多约 81 点，控制使用完整路线点 |
| 路线跟随 | 沿线进度单调投影，防止交叉路线跨段跳跃；局部目标前看 0.8–2.2 m，A* 每约 0.4 s 重规划 | 最多 5000 点、总长 20 km；这里只验证短程模拟，长路线按真实低速耗时执行 |
| 避障和控制 | 随狗移动的 6×6 m 合成观测地图，约 0.70 m 膨胀，0.12 m/s、0.30 rad/s 低速控制；独立 0.52 m 模拟碰撞包络 | 平地运动学模型，无真实步态、制动、玻璃／悬崖／台阶模型；模拟避障不是宇树官方算法 |
| AI 工具与应用同步 | 地图查询、保存完整路线、载入、开始、心跳、停止；路线几何摘要对应缓存预览 | 地图服务只缓存最近四条路线；缓存丢失时不把新任务的位置叠在旧地图上 |

定位状态中 `absoluteFix=false`。人工标定初始误差假设为 3 m／20°，随距离和时间增长，只是保守的软件假设，不是测量得到的精度或置信区间。模拟使用理想位姿真值和固定 0.02 m 假设，不能据此推断 PRO 实际精度。地图上选起点不会自动定位狗，也不会把 Mac 的位置当作狗的位置。

点云采集与快速局部控制独立于模型推理，模型不需要按每一帧发速度。视频在当前地理任务中用于画面监控与新鲜度检查，未接入经过实机验证的道路语义判断。

## Taku Phone 操作

1. Mac 运行 `bash tooling/go2-lab/start-simulation.sh` 和独立的 `bash tooling/go2-lab/start-maps.sh`。前者明确输出 `SIMULATION ONLY`，不会载入实机 transport。个人 Key 已配置在仓库外，不需要再次输入。
2. 恢复 `adb -s emulator-5554 reverse tcp:18845 tcp:18845`、`adb -s emulator-5554 reverse tcp:18846 tcp:18846`，打开机器狗应用。
3. 进入「高德路线」，搜索地点，设置起点和终点，点「规划步行路线」。也可先生成地图，再点「在图上选择终点」、点击地图、重新规划。
4. 验证范围选「先验证前 10 米」，点「载入模拟路线」。这一步重置模拟狗到路线首点，建立虚拟地理参考和合成纸箱场景；不移动真实狗。
5. 点「开始模拟跟随」。观察摄像头、地图箭头、局部路径和进度；点击「停止路线跟随」随时取消。首段完成只显示首段完成，不把它当成公里级路线全部走完。
6. 如需全程模拟，选「全程模拟」后重新载入。不会压缩距离或加速动画；公里级路线按 0.12 m/s 可能需要很长时间。
7. 「实机／人工位置与朝向标定」可输入已知坐标和狗朝向。填入所选起点只是方便输入，必须核对狗确实在该位置。标定使旧路线失效，不解锁实机运动。

手机端 AI 技能位于 `tooling/go2-lab/skill/taku-go2/SKILL.md`，已同步到当前开发模拟器。CLI 入口为 `sh /data/local/agentos/go2-lab/go2`；可使用 `map-search`、`map-route`、`geo-prepare-route`、`geo-start`、`geo-heartbeat`、`geo-state`、`nav-stop`。严格字段示例在技能中，不能用经纬度直接发 Move。

## 停止和失效处理

- 导航只允许不可配置的 `source=simulation`。人工标定、地图查询或客户端字段都无法打开实机导航。
- 操作页面前台约每 0.6 s 续监督心跳，CLI 应每约 1 s 续。超过 3 s 无心跳停止；恢复心跳不会重启任务。离开地图页、切到后台请求停止。
- 位姿新鲜度 0.3 s、点云 0.4 s、接收时间差 0.2 s，以及既有摄像头／控制状态守卫继续生效。失效后不继续盲走。
- 断连／新连接／地图代次变化、坐标系变化或位姿突跳使参考失效。高定位不确定性、偏离路线超过 1.6 m、没有局部通路、长时间无进展均停止。
- 到达需最终点距离小于 0.14 m，停止后再次检查在 0.16 m 内；这些阈值仅在当前模拟模型有效。保留停止未确认的锁定，不通过重启任务绕开。

## 验证证据

测试输出与截图保存在 ignored 的 `out/go2-lab/geo-verification/`，不包含 Key。

- 127 项 Python 测试、16 项 JavaScript 逻辑测试通过，所有浏览器脚本语法检查通过。覆盖坐标／方向、非法数值、路线交叉、代次变化、位姿突跳、过期／时间不同步、心跳丢失、局部阻塞、人工误差门槛、实机禁止、原有控制互锁。
- Android APK 和 CLI 构建成功；修复 Android `Files.readString` 不可用，改为有尺寸上限的流式读取。更新后的 CLI 已推入模拟器。
- 实际 Android WebView 的高德接入通过 6 组验证：真实 POI、步行路线和图片，中英与四种宽度，地图服务故障恢复，查询不触发机器人连接／运动。
- 实际 WebView 的地理界面通过 4 组验证：实时监控、人工标定使旧路线失效、地图真实点击反投影、新终点重新查询；无页面脚本异常。
- 真高德样例路线的几何总长约 5244.37 m（提供方显示距离 5186 m，两者不同），执行其前 10 m；绕过合成纸箱，在终点前约 0.12 m 停止。首次记录耗时 114.73 s，最大横向偏离约 0.90 m，模拟碰撞包络拦截次数 0。`results.json` 保存最新复测，不能宣称走完 5 km。
- 独立完整转弯路线 `(0,0) → (2.5,0) → (2.5,1.5)`：4 m，57.31 s，到终点距离 0.1334 m，最大横向偏离 0.9012 m，碰撞包络拦截次数 0，`arrived` 且停止确认。见 `full-turn-results.json`。
- Android CLI 通过 4 组验证：实际高德查询及完整路线文件、页面同步相同任务和地图、载入／启动／心跳、停止并确认实机仍禁用。见 `cli-results.json`。这是工具集成测试，不是 LLM 自主任务成功率评测。
- 静态地图真实标记探针：zoom=15、scale=1，东西相差 0.003° 的 A/B 标记相差约 140 px。修正为 512×2^zoom 的像素世界比例；独立像素基准测试防止“正反转换自洽但叠错地图”。见 `projection-probe.png`。该比例来自实际响应测量，不声称官方文档明确承诺了此公式。

## 只有 PRO 本体，仍需完成什么

本体可提供相对位姿；不能仅凭 `position`、yaw 和一条高德路线推断地理绝对位置或真北。官方 ROS2 示例明确将 sport position 标为 Odometry frame。软件转换已经实现，但实际误差、漂移和雷达关系必须测量。

下次有狗在现场时先做只读验收：连接并录制静止位姿／雷达／视频；在已知地图位置人工标定朝向；在受控的短距离直行和转向中，核对 sport 与 LiDAR 的轴向、单位、旋转、时间差和重连原点。移动测试需要当次现场条件与授权，当前实现不会自动开始。用独立已知地标对比地图估计误差，不能只用同一套 odom 自证准确。

随后单独验证 PRO 的原生避障查询、启用回读、AI／normal 模式、API 控制来源和停止确认。旧实验中的返回失败不能推导成整机没有原生避障，也不能凭 App 的雷达开关承诺 SDK 路径已生效。最后才能评估开放有限场地实机路线跟随。长距离还需可靠重定位／全局定位及真实可通行地图；这部分目前没有完成，也不能用模拟补出传感器没有提供的证据。
