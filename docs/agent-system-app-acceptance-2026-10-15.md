# System calls and on-phone native app development acceptance

Scope: dedicated Android 16 / API 36 / ARM64 emulator, existing device account, sole TaskBroker / Codex 0.161.0 App Server; no physical Pixel was operated. See the [redacted results](../evidence/builds/2026-10-15-agent-system-app.json).

Subsequent progress: the child processes left behind after stopping, which still occurred when this record was written, were fixed later the same day and verified on the dedicated emulator; see [cancellation and process-cleanup acceptance](agent-cancellation-2026-10-15.md). This update does not change the original results of this app acceptance; see [current status](current-status.md) for the overall project state.

## System entry points tested

Through the real chat UI, the Agent called Settings Provider, Package Manager, Sensor Service, and Battery Service. It set the sleep timeout to 180000 milliseconds and read it back. Independent checks found 183 packages, 12 hardware-interface sensors, and battery level=100/status=4, matching the Agent output. The result JSON was created and reread on the device. The original sleep timeout, 2147483647, was restored afterward.

These are public system states on the emulator, not acceptance of physical-phone sensors, batteries, or hardware. The generated app's SensorManager returned 18 visible sensors, including derived/software sensors, which is a different measure from the hardware-interface count.

## Native development and updates

The Agent created MainActivity.java and Manifest itself on the device. Separately prepared ECJ, D8, aapt2/aapt, zipalign, and apksigner compiled, packaged, and signed on-device, with installation through pm install. No business source was compiled on a computer, no precompiled business shell was used, and there were no web assets. The first version took 186.065 seconds; APK size was 12685 bytes.

App `org.taku.acceptance.systemlab20261015` used ordinary UID 10151 and requested only MODIFY_AUDIO_SETTINGS. It actually read Android APIs, battery, and sensors; AudioManager buttons changed media volume 5→6→5. Adding and undoing A/B scores resulted in A=2/B=0, retained after force-stop and reopening.

The Agent continued editing the same project, upgrading to versionCode=2/versionName=1.1 and updating in place with the same newly created development signature while preserving data, in 117.064 seconds. The second APK was 16781 bytes and added a reset button and ContentProvider. Both APK signatures were independently checked on the host.

## App business API

Activity and ScoreProvider share ScoreStore. The Agent actually called query, score.add, and score.undo; the states progressed 2/0/2→2/3/3→2/3/3 (delta=0 rejected)→2/0/2→4/0/3. The three values are A, B, and historyCount, respectively.

A zero parameter actually threw IllegalArgumentException without changing state; the content CLI process exit code cannot substitute for checking application errors. ContentObserver updated the already-open UI to A=4/B=0 without restart or simulated taps. This model turn took 67.307 seconds.

The Provider is protected by Android's built-in DUMP permission. A separate unprivileged test app (UID 10152) was explicitly denied when querying through normal ContentResolver because it lacked DUMP. This test app is a permission probe supplied by the test framework, not the business application generated by the Agent.

## Reproduction entry points and boundaries

- [System-service request](../examples/scenarios/system-services-probe.txt), [native-development request](../examples/scenarios/native-system-app-probe.txt), [update request](../examples/scenarios/native-system-app-iteration.txt), [app API request](../examples/scenarios/native-system-app-api-probe.txt).

- The [on-device native builder](../tooling/app-kit/build-native.sh) requires an explicit background display ID; dependency tools and new test signing material remain in ignored out/device development directories, outside Git.

The compiler toolchain was prepared separately for this round and is not yet integrated into the ROM or a cross-device one-step installer. This proves only the creation, update, permission, and API loop for one small native app, not arbitrary app development, access to every system permission, an implemented plugin marketplace, or accepted production isolation. Child-process cleanup after stopping was not yet fixed during this app acceptance; see the opening note for the later fix's scope and independent verification.
