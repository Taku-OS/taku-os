## SDK, capability catalog, and device-acceptance definitions

- The general SDK implements three read-only device methods: `system.info`, `displays.status`, `tasks.status`, plus metadata methods `methods.list`, `capabilities.list`, `extensions.list`. Native Agent phone tools/shell execution are not restricted to those three, nor do they imply additional general SDK APIs.
- The [57-capability catalog](android-api-guide.md) still registers 20 emulator-evidence items, 37 research items, and 0 physical-device entries. This is that catalog batch's scope, not yet updated item by item with later Pixel 9 records; **it does not mean the whole project has no physical-device acceptance**, nor 57 callable SDK methods.
- Trusted local `device-report` works through registry → scoped SDK → facade → Android. Extension declarations are not a security sandbox; generic event subscriptions, unified plugin install/upgrade/rollback, third-party UI hosts, and full autonomous extension loops remain to build.
- Conventional apps are confirmed only by scenario: emulator records cover WeChat prelogin and rednote guest-image feeds; Douyin video decoding/rendering remains unresolved, without a claim of complete app compatibility.
