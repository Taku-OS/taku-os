Which baseline fits the goal?

Compare routes by clicking. First probe virtual displays on the stock system, then verify the privileged runtime. Modify system source only if actual testing shows the stock framework cannot meet the goal.

Why not immediately switch to LineageOS / GrapheneOS?

Official LineageOS tokay data currently lists branch 23.2 and requires Android 16 firmware before installation. It supports custom system-service builds, but Android 17 stock firmware must not be mixed directly with its boot/partition packages. GrapheneOS supports Pixel Camera and sandboxed Google Play, which is not the complete stock Pixel system; its distribution-security guarantees cannot be applied directly to a modified build with a broadly privileged root Agent.

Official LineageOS device metadata · Official GrapheneOS usage guidance

How can this route be opened and distributed?

Custom source, ordinary APKs, root integration modules, protocols, and installation/acceptance materials can be separate deliverables. Original project code still uses an internal license; a public license must be chosen before publication. Official Google images restrict modification and redistribution; they should not be packaged as a directly open-source complete Taku ROM. Users should obtain matching baselines officially and integrate custom components on their own devices.

Conflicts the independent display must handle

Policy illustration: toggle proposed task arbitration. These policies are not implemented in Taku or tested on hardware yet.

Independent displays still share app data and accounts; behavior such as singleTask can move existing Activities. IME does not provide two independent keyboards; text input and focus arbitration need separate design. Taku currently uses own-focus/no-steal flags, but missing reflection silently becomes zero and should become an explicit capability check.

What evidence exists for root and display implementation?

Official Magisk modules provide service.sh, file mounts, and sepolicy.rule as a possible privileged-service bootstrap. The latest release found this round was v30.7; release notes do not prove Taku compatibility on the chosen Android 17 build. Official scrcpy v5.0.1 docs cover new virtual displays, app launch, and IME display policy as reusable comparison probes. Upstream Android 17 DisplayManagerService still checks trusted-display permission and requires own-focus with no-steal. Actual Pixel vendor builds, SELinux, and app behavior require hardware tests.
