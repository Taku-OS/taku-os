# Round eleven: interrupted-uninstall recovery

Starting from `d05e7a1`, explicit uninstall synchronously writes a journal before deleting cache. Recovery under lock follows that record to complete plugin-configuration cleanup and deletion of cache/previous-version backup. Deletion is idempotent; journal removal occurs only after cleanup. Explicit installation includes `enabled=true` in the same journal: pre-commit interruption rolls cache back, while post-commit recovery completes the enable-config write. Automatic cache refresh retains its existing behavior of not changing enabled state.

Host tests directly compile transaction source: 11 passed, including exits before/after uninstall journal write, after configuration cleanup, and after two deletion points, checking recovered configuration/cache; also covers explicit-install interruption before/after commit and after enable write. Configuration operations use file doubles, not the actual TOML editor; [host log](round12-host.log). The patch applies to original `rust-v0.161.0`; ARM64 build succeeded, stripped binary SHA-256 `5833b45db4bf3148200656f17ebed5c4b5c581adce07d861f7f4f54e61d71fc5`. Offline structural checks passed.

In an isolated temporary home on `Taku_SkillsLifecycle_20261030` / `emulator-5668`, this binary started real app-server and installed enabled plugin 1.0.0 with 20,000 test files. After observing the first file deletion during uninstall, sent actual SIGKILL; journal and partial cache remained. After restarting app-server, target cache, backup, journal, and plugin configuration entry were all absent; temporary directories were cleaned. The [device log](round12-uninstall-kill.log) is raw probe output; the [screenshot](round12-device-log.png) shows that log in an emulator WebView, not GUI operations or direct filesystem views. The probe requires Python 3.11+ `tomllib`.

Verification boundaries: the device test used isolated app-server, not GUI/broker for the kill; no device test of post-commit installation interruption ran. GUI generic `config/value/write` and `config/batchWrite` still do not share the plugin-store lock, so cross-process configuration linearizability is not guaranteed; other direct writers are also outside the lock. Automatic non-explicit cleanup of invalid remote caches retains old deletion behavior and is outside this explicit-uninstall test. Power-loss durability and complete-ROM boot were not tested.
