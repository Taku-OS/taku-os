## Conversation Activity ownership — confirmed and fixed

HomeActivity and MainActivity share a ReactHost. Using its `currentActivity` for
conversation routes could read or rewrite Home's Intent while chat remained
mounted behind it, leaving the real chat's old Panel route intact.

All conversation route reads, Panel consumption, conversation selection, IME
observation, backdrop, keyboard, collapse and close operations now use one
validated conversation owner. A tracked MainActivity wins over the current Home;
destroyed/finishing instances are rejected, with a valid current chat as fallback.
The module seeds the owner when initialized after MainActivity has resumed, and
updates/releases it through Activity lifecycle callbacks. The device regression
caught the missing late-initialization seed before acceptance; it is fixed in
`40aa796` after the initial isolation change in `5ca359c`.

The separate instrumentation APK invokes the actual registered Expo module while
ReactHost's current Activity is Home. It verifies chat route reads, selection,
consumption of a Panel launch, unchanged Home Intent and IME observer ownership.
It uses an unminified same-source target to inspect internal ownership, never a
new stand-in module or a production debug endpoint. Durable launch consumption
remains in the existing preferences; no new state or Agent API is introduced.
