# Try-on failure card in the SystemUI island

Terminal try-on failures now expand the existing top SystemUI rich-content card instead of opening the app's bottom overlay. The card body is opaque `#121212`. Actions follow Figma `I1Dvy3RgXekaDch8WLImiM`, frame `124:62151`: equal fill widths, 8dp gap, minimum 40dp height, full pill radius; Close is white 8% with white 80% text, Retry is white with `#1B1B1B` text. Desktop Figma inspection confirmed the action nodes `124:62204` and `124:62205`; the connector required reauthentication, so no connector-derived design data is claimed.

SystemUI owns the actual top window and touch boundary. A signature-bound content service supplies its body through the existing Messenger v1/SurfaceControlViewHost contract. It checks the real SystemUI sender UID, current card token and bounded surface dimensions. No SystemUI source or APK was changed by this work. The native notification now includes the Icon required by its compact picture reference; a missing reference previously made host extraction reject the notification.

Close, notification actions and the rich buttons share current-token validation. Retry is a direct one-shot Activity PendingIntent and must claim the current token before Activity UI initialization or retry handling. Expired/replaced/dismissed/process-lost tokens cannot retry. The card does not automatically retry or start a camera. Existing model admission, cleanup and the 60-second session limit are unchanged.
