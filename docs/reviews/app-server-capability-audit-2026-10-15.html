Which other App Server capabilities
could become phone experiences?

The phone already has conversations, sign-in, text streaming, Stop, and system-tool execution. The next useful additions are instructions during execution, model selection, question cards, and actual step displays, rather than another chat engine.

Model catalogs and tool metadata do not establish acceptance of every individual call.Official OpenAI App Server documentation

Clarify current boundaries first

Already used on the phone:Native conversation start/resume/read/list/rename, sign-in state and flow, task start/stop, reply streaming, and general command/MCP status.
Already in new source, awaiting phone deployment:Skills catalog and toggles, skill inputs, dynamic context injection, and token-usage recording. These already exist and should not be rebuilt as entirely new features.
Architectural distinction:harness/read and skills/community/* are our bridge interfaces; the new calls actually connected to App Server are skills/list, skills/config/write, and thread/inject_items.

Gaps by phone experience

P0Not integrated

Add instructions during execution

Add a location, constraint, or correction while the assistant executes, without stopping first.

turn/steer

Current sending logic has no steer; it must bind expectedTurnId.

P0Not integrated

Model and reasoning-level selection

Choose a model and reasoning level in settings, beyond concise/detailed response style.

model/list · turn/start

The phone read-only probe returned 7 catalog models; the other models were not individually tested for real generation. model and effort are separate parameters.

P0Not integrated

Necessary-information question cards

When route, account, time, or similar information is needed, show choices and return the user answer to the current task.

item/tool/requestUserInput · mcpServer/elicitation/request

The current client returns -32601 to every server request. Ask only when required information is missing; do not add general confirmation gates.

P0Partially integrated

Actual task steps and progress

Show steps, current stage, and failure location, improving on generic execution status alone.

turn/plan/updated · item/mcpToolCall/progress · item/commandExecution/outputDelta

Text streaming and generic tool status exist; plans and extended progress are not fully rendered. Model internal reasoning need not be exposed.

P0Experimental / awaiting acceptance

Structured phone tools

Expose app launch and foreground/background display observation and control as tools with parameter schemas.

thread/start.dynamicTools · item/tool/call

dynamicTools is experimental; the current interactive-request handler rejects item/tool/call, and system operations mainly use runtime commands.

P1Partially integrated

Context usage, quota, and compaction

Show context and quota status; provide native compaction when long conversations approach the limit.

thread/tokenUsage/updated · account/rateLimits/read · thread/compact/start

New source already records tokenUsage; that module is not deployed on the phone, and quota/manual compaction have no entry. The read-only quota interface was verified.

P1Partially integrated

Apps and MCP product entries

Show available connectors and tools, make connection state clear, and handle interactive requests.

app/list · app/read · mcpServerStatus/list · mcpServer/tool/call · config/mcpServer/reload

The phone discovered codex_apps and 264 tool metadata records; generic mcpToolCall events are already displayed. Metadata count does not establish call acceptance or asset authorization for every tool.

P1Not integrated

Conversation branching, archiving, and search

Try another approach with the same context, organize history, and search/pin conversations.

thread/fork · thread/archive · thread/unarchive · thread/list · thread/metadata/update

The current list takes a fixed 100 entries, without complete pagination, search, or branching. Permanent deletion should be presented distinctly from archiving.

P1Not integrated

Native goal management

Store long-task objectives, status, and token budgets for continued work across turns.

thread/goal/set · thread/goal/get · thread/goal/clear

Goal status is not scheduled wakeup; Android background survival and timed scheduling still need separate integration.

P1Experimental / awaiting acceptance

Realtime voice conversations

Speak directly after holding the power button and receive text or voice responses.

thread/realtime/start · thread/realtime/appendAudio · thread/realtime/appendText · thread/realtime/appendSpeech · thread/realtime/listVoices · thread/realtime/stop

Experimental protocol from phone runtime 0.161.0; service availability, audio capture, playback, interruption, and power use were not verified. This does not establish integration with the general Realtime API.

P2Experimental / awaiting acceptance

Native task queue and multiple agents

Natively order pending tasks and show parent-child task relationships.

thread/queue/add · thread/queue/list · thread/queue/reorder · thread/queue/start · thread/start.multiAgentMode

TaskBroker already has a queue. Before adopting the native queue, decide ownership of state to avoid two independent schedulers. multiAgentMode was not accepted on the phone.

P2Experimental / awaiting acceptance

Remote development and control

Observe and debug the phone runtime from authenticated clients without a USB cable.

remoteControl/status/read · remoteControl/pairing/start · app-server --listen ws:// · codex --remote

The CLI supports remote connections; native remoteControl pairing is experimental. No network listener or remote channel was opened this round.

P2Not integrated

Development workbench

Develop code, run programs, inspect files, and review code on the phone.

review/start · command/exec · process/spawn · fs/readFile · fs/watch · hooks/list

Model-integrated command execution exists; these direct-control RPCs have no product entry yet. hooks/list is readable, with no hooks in the current working directory. review/start reviews code, not arbitrary phone-action acceptance.

Skills and Harness

Inspect/select skills, append device context when needed, and record usage.

skills/list · skills/config/write · thread/inject_items · turn/start.input.skill · thread/tokenUsage/updated

Implemented in new source and settings entries; the phone APK is currently v43, and the installed broker matches the earlier hardware-acceptance SHA, without these new modules.

P2Experimental / awaiting acceptance

Plugin and marketplace management

Manage official plugin marketplaces and plugins together.

marketplace/add · plugin/list · plugin/read · plugin/install · plugin/uninstall

Official documentation explicitly marks some plugin methods as under development and says not to call them from production clients; existing Skills community installation is not the native plugin marketplace.
