# Live Feed integration — 2026-11-12

Target: `emulator-5586`, `Taku_Launcher_Verify`, hardware GPU. Existing userdata
and desktop layout were preserved. This is **not yet a completed live-model E2E acceptance**.

## Changes

- Production Feed uses published cards only. The sample source and its repeating
  pages are test fixtures, not a live source. No sample pins are seeded.
- Upgrade drops source-only pin/removal state while preserving published cards,
  pin order and hidden cards. A push-only repository is ready immediately, including
  first install and reset, so `feed/generate` does not wait for a nonexistent page.
- Card rendering, long press, pin/unpin, ordering, removal and actions continue to
  use the existing repository and UI.
- `content://org.agentos.memory.open-access` exposes `nudges` from the same store
  as the Suggestions screen, so ordinary device-local Agent callers can read
  recommendation IDs and feedback without the legacy signature permission.

## Device configuration

Enabled `enabled`, `analysisEnabled`, `queryEnabled`, `nudges`, `feedCards`.
`feedDescribe` stays false: Memory's fixed-template recommendations use the existing
JSON-render body and do not require a second model call for layout.

Selected installed sources: Calendar, Messaging, Gmail, Maps and WebView Browser
Tester. Enabled the observation accessibility service, separately granted
`NotificationTap` access, and granted Memory notification permission. The local,
gitignored emulator startup bundle now restores these settings and contains the
updated Home and Memory APKs. No model credentials are stored in that bundle.

## Remaining blocker and continuation

The emulator has no signed-in model account, no configured provider and an empty
system-AI model catalog. Memory reports `model:""`, queued records and zero analysis
attempts. Opening switches cannot resolve this. Login/configuration requires the
user's account; do not copy credentials from another device or invent recommendations.

After the user connects a model in Taku AI:

1. Read Memory open-access `status`: check model, selected sources, service connection
   and all requested flags. Wait for queued records to become analyzed; `get`/`browse`
   expose the actual results. Verify model errors rather than publishing test output.
2. Run ordinary Memory organizing (`maintain`) on real captured content and verify
   the board/user card. A bedtime brief is conditional (after 20:00), and message
   nudges require a new selected-app notification related to existing memories.
   Not every captured page should produce a recommendation.
3. Read `nudges` and match each nonempty `card` to Feed `feed/get`/`feed/list`, then
   inspect that real card in the GUI. Pin or remove it, reopen Memory to trigger
   feedback polling, and verify the same reminder's `feedback`/`reactions`.
4. Verify expiry/withdrawal on owned test records separately; do not reset the Feed
   or overwrite real recommendation state to force an outcome.
