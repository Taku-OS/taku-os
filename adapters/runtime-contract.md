# Agent runtime adapter boundary

Status updated: **2026-10-19**. Codex 0.161.0 has scoped execution evidence on the development emulator and Pixel 9 v44; assistant v54 and v55/v56 Magpie integration are committed, with the latest implementation at `a547672`. v55/v56 passed emulator acceptance, but the complete latest ROM has not yet been rebuilt successfully. See [current status](../docs/current-status.md), [native device client](../docs/native-codex-implementation-2026-10-15.md), and [Magpie acceptance](../docs/reviews/magpie-runtime-2026-10-19/README.md).

The current phone model runtime is the image-pinned Codex CLI 0.161.0 App Server. The existing root TaskBroker is the only scheduler, and the task directory is the only entry point for task lifecycles; native App Server threads/turns/items are the conversation source of truth. The UI's `agent-view` is a disposable projection, not a second conversation database.

`adapters/codex-runtime/` owns the pinned binary, bootstrap, and launcher; `system/assistant/broker/CodexAppServer` owns the persistent stdio connection, request/event correlation, native multiple conversations, and real interruption. Home-screen one-shot tasks and chat use the same App Server. Protocol fields must be checked against schemas generated for the actual phone version, not the version installed on a computer.

Device authentication stays exclusively in private runtime directories on the device. The ChatGPT connection confirms account status through real `account/read` calls; the UI consumes status from a controlled in-memory endpoint and does not read, copy, or export authentication caches. Source code, log summaries, and generic ROM releases must not contain account authentication. The phone's account connection screen supports native login initiation/cancellation and status queries; authorization challenges reach the UI only through a controlled in-memory socket, and queue acknowledgement files contain no codes, URLs, or tokens. After user authorization, real emulator chat and Android getprop commands passed acceptance on October 14, followed by model use and selected native operations on Pixel 9 on October 15. See [Agent module](../docs/agent-module.md) and [device record](../docs/native-codex-implementation-2026-10-15.md).

The on-device Magpie model gateway is integrated with the same Codex App Server. It routes model services; Codex remains the Agent runtime. DeepSeek inference calls its online API, not offline inference on the phone. `adapters/magpie-runtime/` manages the official Android binary, checksums, launcher, and init service; `ModelConnection` manages connection selection through controlled in-memory IPC, while Magpie manages provider configuration and keys in device-private directories. Magpie status comes from the local gateway and model catalog, not ChatGPT account login status. The model catalog uses the native Codex catalog interface; messages and tool calls remain native threads/turns/items without adding another queue or task-state authority. Connections switch only while idle, restarting App Server and resuming the original conversation on the next turn. See [on-device Magpie adapter](magpie-runtime/README.md). As of this update, its real DeepSeek, protocol, and navigation evidence is limited to the development emulator; physical phones and a complete ROM have not passed acceptance.

Replacing the entire Agent runtime remains an extension direction; Magpie integration does not complete that work. Future adapters should receive the existing taskId, prompt, context, and capability interfaces and return events and terminal states to the same lifecycle, without creating another queue or task-state authority. Read-only SDK capabilities are independent of Codex and can be called directly by trusted programs. See [Agent module](../docs/agent-module.md) for details.
